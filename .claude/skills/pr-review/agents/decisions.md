# 観点: 決定記録（DR）との整合

## 何を守っているのか

`docs/decisions/` にある DR は、このプロジェクトの判断の根拠をすべて記録している。各 DR には「文脈 / 決定 / 理由 / 検討した他の選択肢と却下理由 / 帰結」がある。

DR が価値を持つのは、**実装が DR に従っているとき**と、**新しい判断が DR として記録されるとき**だけだ。どちらかが崩れると、DR は「昔こう考えていた」という化石になり、半年後に同じ議論をやり直すことになる。

## 見るべきこと

**DR に反する実装**。差分が、既存の DR で却下された選択肢を採用していないか。DR の「決定」節と矛盾していないか。矛盾しているなら、それは実装のミスか、DR を更新すべき状況のどちらかだ。**どちらなのかまで踏み込んで書く。**

**記録されていない決定**。実装中に判断したことが DR に無いまま入り込んでいないか。判断とみなす目安は「他の選択肢がありえて、選んだ理由を後から聞かれうるもの」。ライブラリの選定、ファイル構成の方針、命名規約、閾値の設定、抽象の切り方などが該当する。単なる実装の詳細（変数名、行の並び）は該当しない。

**DR に値が複製されていないか**。DR-0024 の方針により、デザインの値（色、閾値、スケール）は DR に書かず、正本（`DESIGN.md` / `design/tokens.json` / `design/rules.json`）へのリンクだけを持つ。値を含む DR には `**正本**:` 行がある。新しい DR がこの方針を破っていないか。

**帰結の追従**。DR の「帰結」節に書かれたことが実装されているか。あるいは、実装によって新しい帰結が生まれたのに DR に反映されていないか。

**置き換えの扱い**。既存の決定を覆す場合、旧 DR を削除するのではなく、新しい DR を立てて旧 DR の状態を「置き換え済み」に変える運用になっている。差分がこれに従っているか。

**リンクの健全性**。DR 間の相互リンクが解決するか。新しい DR が索引（`docs/decisions/README.md`）に追加されているか。

## 報告するときの注意

「DR に反する」と言うなら、**DR番号と該当箇所を引用すること**。DR は長いので、どの一文に反しているかまで示さないと確認に時間がかかる。

「記録されていない決定がある」と言うなら、**その決定に他の選択肢が実在したことを示すこと**。選択の余地が無かったものは決定ではない。

Issue の説明や PR の説明に判断の理由が書かれている場合、それは「DR に昇格すべき候補」として扱う。PR の説明はマージ後に読まれないが、DR は残るからだ。
