# `docs/reviews/pr-<N>.md` の書式

そのPRのレビュー全文。指摘の本体はここに残る。後から「あのとき何を言われたか」を追えるようにするのが目的なので、要約しすぎない。

```markdown
# PR #<N> レビュー

- **タイトル**: <PRのタイトル>
- **レビュー日**: <YYYY-MM-DD>
- **対象**: <baseRefName>...<headRefName>
- **変更ファイル数**: <n>
- **立った観点**: <この周に**立てた**観点をすべて `/` 区切りで。指摘ゼロだったものも、結果を返さなかったもの（`（結果なし）` を添える）も書く>

## 要約

<blocker の件数、should の件数、consider の件数。1〜3文で全体の所感>

## blocker

### <カテゴリID> — <一行要約>

- **場所**: <path>:<line>
- **指摘した観点**: <観点名>（複数から挙がった場合はすべて列挙）
- **累計**: <このカテゴリの通算回数>回目
- **何が起きているか**: ...
- **なぜ問題か**: ...
- **失敗シナリオ**: ...
- **提案**: ...

## should

<同じ形>

## consider

<同じ形>

## 落とした指摘

<統合時に検証して成立しなかった指摘。カテゴリIDと、なぜ成立しないと判断したかを一行ずつ。
 空なら「なし」と書く。ここを残すのは、次に同じ指摘が出たときに判断をやり直さないため>

## ルール化候補

<このレビューで累計3回以上になったカテゴリ。無ければ「なし」>

- `<カテゴリID>` — 通算<n>回。<どんな検査ルールにできそうか、1〜2文>
```

## 書くときの注意

**「複数観点から指摘された」ことを消さない。** 独立した観点から同じ問題が見えたなら、それは強い信号だ。

**立った観点を必ず書く。指摘ゼロだった観点も含める。** 初回は冒頭欄に、再レビューではその周の節の冒頭に、どちらも `- **立った観点**: …` の行で置く。この項目は必須で、省略も「省略」と書くこともできない。

**書くのは「立てた」観点で、結果を返さなかったものにはその旨を添える。** 立てた観点と結果を返した観点は同じとは限らない（立てた ⊇ 返した）。収束の条件は「絞られずに立ったこと」と「そのすべてが結果を返したこと」の2つで、どちらも判定するには両方が読み取れる必要がある。

**観点名は `pr-review/SKILL.md` の観点表の表記をそのまま使い、`/` で区切る。** 「全観点」のような総称で代えない。どれが立ったかが残らなければ、絞られたかどうかを確かめられない。

**結果を返さなかった観点も、`/` 区切りの要素として書く。** 注記は `（結果なし）` の一語に限る——理由も補足も足さない。列の外へ括弧で逃がすと、`/` で数えたときにその観点が消える。注記へ理由や補足を書き足すと、そこに `/` が混ざって要素数がずれる。どちらの場合も、**立てたのに落ちた周**と**最初から絞られた周**が同じ要素数になって区別できなくなる。**なぜ落ちたかは、その周の所感の地の文へ書く。**

指摘から辿れるのは、指摘が出た観点だけだ（各指摘の `指摘した観点` 欄）。**指摘ゼロで返った観点は、ここに書かなければどこにも残らない。** `issue-workflow` はこの記録で「その周に観点が絞られたか」を判定し、絞られた周を収束に使わない（[DR-0052](../../../../docs/decisions/0052-review-loop-third-exit.md) 決定1 / [DR-0053](../../../../docs/decisions/0053-review-coverage-recorded.md)）。書かなければ、あちらは確かめられず確認未了へ倒すことになる。

**`指摘した観点` 欄とは別物である。** あちらは1件の指摘がどの観点から挙がったかで、こちらはその周に何が走ったかだ。片方からもう片方は導けない。

**再レビューでは既存の節を消さない。** 同じ PR を何周も回すことがある。2周目以降は `## <N>周目（YYYY-MM-DD）` の節を末尾に追記し、その周の指摘だけをそこへ書く（`<N>` はその周の通し番号。3周目なら `## 3周目`）。節の冒頭は次の形にする。

```markdown
## <N>周目（YYYY-MM-DD）

- **立った観点**: <この周に立てた観点をすべて。初回の冒頭欄と同じ書き方>

<対象の増分と、その周の所感>
```

前の周の内容を上書きすると、PR 本文が指す「レビュー全文」から最初の blocker が存在した事実が消える。何を指摘され、それがどう直ったかの経過こそが、このファイルを残す理由だ。

**落とした指摘の節を省略しない。** ここが空でも「なし」と書く。次回の統合で同じ判断を繰り返さないための記録なので、空欄と「なし」は意味が違う。
