# `docs/reviews/pr-<N>.md` の書式

そのPRのレビュー全文。指摘の本体はここに残る。後から「あのとき何を言われたか」を追えるようにするのが目的なので、要約しすぎない。

```markdown
# PR #<N> レビュー

- **タイトル**: <PRのタイトル>
- **レビュー日**: <YYYY-MM-DD>
- **対象**: <baseRefName>...<headRefName>
- **変更ファイル数**: <n>

## 要約

<blocker の件数、should の件数、consider の件数。1〜3文で全体の所感>

## blocker

### <カテゴリID> — <一行要約>

- **場所**: <path>:<line>
- **指摘した観点**: <観点名>（複数から挙がった場合はすべて列挙）
- **累計**: <このカテゴリの通算回数>回目
- **何が起きているか**: ...
- **なぜ問題か**: ...
- **失敗シナリオ**: ...
- **提案**: ...

## should

<同じ形>

## consider

<同じ形>

## 落とした指摘

<統合時に検証して成立しなかった指摘。カテゴリIDと、なぜ成立しないと判断したかを一行ずつ。
 空なら「なし」と書く。ここを残すのは、次に同じ指摘が出たときに判断をやり直さないため>

## ルール化候補

<このレビューで累計3回以上になったカテゴリ。無ければ「なし」>

- `<カテゴリID>` — 通算<n>回。<どんな検査ルールにできそうか、1〜2文>
```

## 書くときの注意

**「複数観点から指摘された」ことを消さない。** 独立した観点から同じ問題が見えたなら、それは強い信号だ。

**落とした指摘の節を省略しない。** ここが空でも「なし」と書く。次回の統合で同じ判断を繰り返さないための記録なので、空欄と「なし」は意味が違う。
