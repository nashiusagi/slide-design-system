# PR 本文の書式（仕上げ時）

着手時の本文を、最終的な差分に合わせて置き換える。

```markdown
Closes #<Issue番号>

## 何を変えたか

<1〜3行。差分の全体像を、ファイル名ではなく振る舞いで説明する>

## 変更点

- `<パス>` — <何をどう変えたか>
- `<パス>` — <何をどう変えたか>

## なぜこうしたか

<選択肢があった箇所だけ書く。自明な実装は書かない>
<設計上の決定を含むなら、対応する DR へのリンクを置く>

## レビューでの指摘と対応

- <指摘の要約> → <どう直したか>
- <見送った指摘> → <なぜ見送ったか>

レビュー全文: `docs/reviews/pr-<N>.md`

## 確認方法

<レビュアーが手元で確かめる手順。無いなら「差分の読解のみ」と書く>
```

## 書くときの判断

**`Closes #<N>` を消さない。** マージ時の Issue 自動クローズがこの行に依存している。

**「変更点」はファイルの羅列にしない。** 差分を見れば分かることを繰り返しても読み手は増えない。そのファイルで何が変わったかを一言で言う。

**「なぜこうしたか」は、選択肢があった箇所だけ。** 他に選びようがなかった実装に理由は要らない。

**「レビューでの指摘と対応」は、指摘がゼロだったなら「指摘なし」と一行で書く。** 節ごと消すより、レビューを通したことが残る方がよい。
