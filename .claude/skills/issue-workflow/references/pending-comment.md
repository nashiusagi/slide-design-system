# 残指摘コメントの書式（レビューループ打ち切り時）

レビューの上限周回を終えても `blocker` / `should` が残った場合、または `should` を見送ると判断した場合に、PR へコメントする。上限は `SKILL.md` の手順5が正本で、ここでは数字を持たない。

**未対応の指摘がゼロなら、こちらではなく `unconfirmed-comment.md` を使う**（[DR-0052](../../../../docs/decisions/0052-review-loop-third-exit.md)）。残っていないものを「残指摘」として出すと、本文でそれを打ち消すことになる。

```markdown
レビューを <n>周したが、以下が残っている。ここから先は判断が要ると考えて、いったん手を止めた。

最後の周: <立った観点>。やり直し <回数。無ければ「無し」>

## 残っている指摘

- **[blocker] <指摘の要約>**
  <なぜ収束しなかったか。試したことと、そのどれが効かなかったか>
- **[should] <指摘の要約>**
  <同上>

## 対応済みの指摘

<残っていない側も並べる。各 `blocker` / `should` を1行ずつ、直したのか見送ったのかを書く。
 見送った `consider` も同じ一覧に入れる——次に読む人が「見落とし」と「見送り」を区別できる。
 残指摘の数え方を読み手が再現できる形にしておく（[DR-0052](../../../../docs/decisions/0052-review-loop-third-exit.md)）>

- **[blocker] <指摘の要約>** — 直した（<どう直したか>）
- **[should] <指摘の要約>** — 直した（<どう直したか>）
- **[consider] <指摘の要約>** — 見送った（<理由>）

## 見立て

<残指摘の共通の原因についての推測。「実装の問題ではなく Issue の前提が曖昧」など>

レビュー全文: `<pr-review が返したレビューファイルのパス>`
```

## 書くときの判断

**最後の周に立った観点とやり直し回数を書く。** どの抜け方で終わっても、判定に使った条件が残る形にする（`SKILL.md` 手順5）。観点は、レビュー記録の「立った観点」欄をそのまま写す——呼ぶときに何を頼んだかではない。

**「直せませんでした」で終わらせない。** 何を試して、どこで行き詰まったかが無いと、引き取る人が同じ道を最初から辿ることになる。

**上限まで回しても収束しない指摘は、たいてい実装ではなく前提に原因がある。** Issue のスコープが曖昧、正本と要求が矛盾している、そもそも別の作り方が要る。「見立て」にはその推測を書く。外れていてもよい。判断の出発点になる。

**このコメントを出した PR に完了コメント（`completion-comment.md`）を重ねない。** 終わっていないものを終わったと報告することになる。打ち切りの場合は、このコメントが最終報告になる。
