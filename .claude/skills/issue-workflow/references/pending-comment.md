# 残指摘コメントの書式（レビューループ打ち切り時）

レビューの上限周回を終えても `blocker` / `should` が残った場合、または `should` を見送ると判断した場合に、PR へコメントする。上限は `SKILL.md` の手順5が正本で、ここでは数字を持たない。

```markdown
レビューを <n> 周したが、以下が残っている。ここから先は判断が要ると考えて、いったん手を止めた。

## 残っている指摘

- **[blocker] <指摘の要約>**
  <なぜ収束しなかったか。試したことと、そのどれが効かなかったか>
- **[should] <指摘の要約>**
  <同上>

## 見立て

<残指摘の共通の原因についての推測。「実装の問題ではなく Issue の前提が曖昧」など>

レビュー全文: `<pr-review が返したレビューファイルのパス>`
```

## 書くときの判断

**「直せませんでした」で終わらせない。** 何を試して、どこで行き詰まったかが無いと、引き取る人が同じ道を最初から辿ることになる。

**上限まで回しても収束しない指摘は、たいてい実装ではなく前提に原因がある。** Issue のスコープが曖昧、正本と要求が矛盾している、そもそも別の作り方が要る。「見立て」にはその推測を書く。外れていてもよい。判断の出発点になる。

**このコメントを出した PR に完了コメント（`completion-comment.md`）を重ねない。** 終わっていないものを終わったと報告することになる。打ち切りの場合は、このコメントが最終報告になる。
