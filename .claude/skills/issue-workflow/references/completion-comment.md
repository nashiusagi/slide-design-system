# 完了コメントの書式

**収束して抜けたとき**（指摘ゼロのレビューを1周通ったとき）に、PR へコメントする。確認未了・打ち切りで抜けたときは出さない（[DR-0052](../../../../docs/decisions/0052-review-loop-third-exit.md)）。

```markdown
実装が完了した。

- 実装: <一行で何をしたか>
- レビュー: `pr-review` を <n>周実施。<blocker n件 / should n件> を反映済み
- 最後の周: <立った観点>。やり直し <回数。無ければ「無し」>
- 観点が絞られていないこと: <レビュー記録のどの周の「立った観点」欄で確かめたか>
- 残っている判断: <指摘に紐付かない開いた論点（Issue の前提、設計の選択）があれば。無ければ「なし」。見送った `consider` は下の一覧に書き、ここへは重ねない>

## 対応済みの指摘

<各 `blocker` / `should` を1行ずつ、直したのか見送ったのかを書く。見送った `consider` も同じ一覧に入れる。
 収束は最も強い合図なので、記録の義務を他の2つの抜け方より緩くしない（[DR-0052](../../../../docs/decisions/0052-review-loop-third-exit.md)）>

- **[blocker] <指摘の要約>** — 直した（<どう直したか>）
- **[should] <指摘の要約>** — 直した（<どう直したか>）
- **[consider] <指摘の要約>** — 見送った（<理由>）

マージの可否は判断してほしい。
```

## 書くときの判断

**このコメントは通知として届く。** PR 本文が「何を変えたか」の正本で、こちらは「終わった・見てほしい」の合図。本文の内容をここへ複製しない。

**レビュー周回数を書くのは、どれだけ詰めたかが分かるようにするため。** 1周で指摘ゼロだったのか、上限まで回して収束したのかで、読み手の警戒度は変わってよい。

**最後の周に立った観点とやり直し回数を省かない。** 収束は「観点が絞られずに立ち、そのすべてが結果を返した周」でしか成立しない（`SKILL.md` 手順5）。その条件を満たしたことが残らなければ、収束という判定は書き手の申告にしかならない。

**観点が絞られていないことは、確かめた場所を添えて書く。** この書式だけが他の2つより1項目多いのは、絞り状態が効くのが収束の判定だけだからだ。確認未了・打ち切りは未対応の指摘の数で決まり、観点が絞られていたかは判定を変えない（それでも、後から読む人のために立った観点は残す）。**伝えたことを根拠にしない**——`pr-review` は要望を受け取る項目を持つが（あちらの手順1）、伝えたことと実際に立ったことは別だ。確かめる先はレビュー記録の「立った観点」欄になる（`SKILL.md` 手順5）。

**見送った `consider` を省かない。** 収束はマージ判断の材料になる合図で、そこだけ記録が緩いと、面倒な `consider` を見送って完了報告へ抜ける方が楽になる。

**マージは人が決める。** コメントで催促しない。判断材料を渡すだけにする。
