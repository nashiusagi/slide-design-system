# DR-0005: 自分専用の単一テーマとし、primitive 層を持たない

- **状態**: 承認済み
- **日付**: 2026-09-06
- **関連**: [DR-0007](./0007-north-star.md), [DR-0008](./0008-accent-hue-purple.md)

## 文脈

デザイントークンの層構造は適用範囲で決まる。複数ブランドやテーマ差し替えを想定するなら、色の生値を持つ primitive 層と、用途を表す semantic 層を分ける必要がある。単一テーマならその分割は過剰になる。

## 決定

自分一人が使う単一テーマとして設計する。トークンは semantic 層のみのフラット構成とし、primitive 層とテーマ差し替え機構は作らない。

## 理由

- Atlas も semantic 層のみの構成（12 色フラット）で、`Dark Mode: not planned` と明記して意図的に絞っていた。単一テーマでは層を分けても参照が一段増えるだけで得るものがない
- 層を減らした分の労力を契約と検査へ回せる
- 後から primitive 層を割ることは可能。逆に、最初から二層にして使わないコストは戻ってこない

## 検討した他の選択肢

### チーム / 社内共通基盤

複数人・複数ブランドで使う前提。primitive 層と差し替え機構を持つ。

**却下理由**: 現時点で利用者は一人。将来の要求に備えた抽象は、要求が現れるまで検証されない。

### OSS 参照実装として公開

**却下理由**: 公開自体は行う（[DR-0023](./0023-public-repo-with-audit.md)）が、「他人が自分のテーマを当てられること」を設計目標には置かない。

## 帰結

- ダークモードは対象外。将来必要になったら DR を追加して層構造から見直す
- トークンの値は [DR-0007](./0007-north-star.md) / [DR-0008](./0008-accent-hue-purple.md) の方針に従い、`design/tokens.json` が正本となる
