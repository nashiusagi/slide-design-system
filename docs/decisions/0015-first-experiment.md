# DR-0015: 第 1 弾のお題は「この仕組み自体の紹介スライド」とする

- **状態**: 承認済み
- **日付**: 2026-09-06
- **関連**: [DR-0014](./0014-baseline-comparison.md), [DR-0010](./0010-three-layouts.md)

## 文脈

Baseline 比較（[DR-0014](./0014-baseline-comparison.md)）を行うには具体的なお題が要る。お題は「AI が素で作ると壊れやすい」性質を持たないと差が出ない。情報量が多くて枚数が要る、箇条書きの粒度が揺れやすい、文字がはみ出しやすい、といった性質である。

## 決定

「Design Harness をスライドに適用するとどうなるか」を説明する 10〜15 枚を第 1 弾のお題とする。

## 理由

- ドッグフーディングになる。契約を書くときに題材の中身を考える必要がない（既に頭にある）
- そのまま登壇やブログの素材として使える。実験の成果物が捨てにならない
- 説明的な内容は箇条書きが増え、文字量が揺れやすい。`no-overflow` と `deck-conformance` の効きを試すのに適する

## 検討した他の選択肢

### 実際に控えている発表

実用価値が最も高い。

**却下理由**: 仕組みが未完成の段階で、締切のある仕事を乗せるリスクがある。

### 中立な技術題材（架空の技術紹介）

自己言及のバイアスが入らず、比較実験としては最もフェア。

**却下理由**: 成果物が捨てになる。

## 帰結

- 3 種の layout（[DR-0010](./0010-three-layouts.md)）で表現できる構成に制約される
- 自己言及的な題材のため、「契約を知っている AI が有利になる」バイアスがありうる。結果の解釈時に留意する
