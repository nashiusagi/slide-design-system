# DR-0002: AI が生成するソースは JSX / React とし、静的出力へビルドする

- **状態**: 承認済み
- **日付**: 2026-09-06
- **関連**: [DR-0011](./0011-lint-and-measure.md), [DR-0022](./0022-plain-vite-build-output.md)

## 文脈

最終成果物が HTML + CSS + JS であることは確定している。しかし AI が直接書く「ソース」の形は別に決められる。この選択が、契約違反をどう検出するか（静的検査の実装方法）を根本から決める。

## 決定

AI は JSX / React を書く。`vite build` で静的な HTML + CSS + JS へ出力する。

## 理由

- ESLint の AST 検査が使える。参考元のデザインシステムが持つ ESLint プラグインが実証した検査手法（承認外コンポーネントの検出、生の色値の検出、Example が要求した部品の実装確認）をほぼそのまま移植できる
- JSX は構造が明示的で、「どの layout を使ったか」「どのコンポーネントを使ったか」を確実に判定できる。素の HTML では class 名の慣習に頼ることになり、検査が脆くなる
- コンポーネントとして機構を提供できるため、AI がスライドの表示機構を再発明しない

## 検討した他の選択肢

### 素の HTML を直接生成する

ビルド不要で、生成物がそのまま成果物になる。

**却下理由**: HTML / CSS の AST を自前でパースして lint を書く必要があり、実装コストが高い。また AI が構造を崩しやすく、契約適合の判定が曖昧になる。

### Markdown → ビルド

**却下理由**: AI の自由度が低すぎ、ビルダがすべてを保証してしまうため検査の意味が薄れる（[DR-0001](./0001-phase-1-is-ai-harness.md) と衝突）。

## 帰結

- ソースと成果物が乖離する。measure 検査（[DR-0011](./0011-lint-and-measure.md)）は**ビルド出力に対して**行い、本番と同一の物を検査する
- React / TypeScript / Vite が必須依存になる
