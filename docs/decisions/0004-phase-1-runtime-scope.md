# DR-0004: Phase 1 のランタイムはスケーリングと URL 同期のみとする

- **状態**: 承認済み
- **日付**: 2026-09-06
- **関連**: [DR-0003](./0003-custom-slide-runtime.md), [DR-0001](./0001-phase-1-is-ai-harness.md)
- **正本**: `design/tokens.json`（`canvas`）

## 文脈

ランタイムを自作すると決めた（[DR-0003](./0003-custom-slide-runtime.md)）以上、どこまで作るかを決める必要がある。発表者ビューや PDF 出力は実用上価値があるが、実装量は機構本体を上回りうる。

## 決定

Phase 1 では `Deck` / `Slide` / `Fragment` と、固定キャンバスのスケーリング、URL による現在位置の同期のみを実装する。キャンバスの寸法は `design/tokens.json` の `canvas` を正本とする。`Slide` は `notes` を props として受け取るが表示はしない。

## 理由

- Phase 1 で証明したいのは「AI が生成したスライドの妥当性を機械判定できるか」であり、発表者ツールの充実ではない
- 固定キャンバスのスケーリングは省略できない。これがあるからレイアウトが画面幅で崩れず、その結果「はみ出し」が機械判定可能な違反になる（[DR-0011](./0011-lint-and-measure.md) の中核）
- ノートをデータとして受け取っておけば、表示 UI は後からいつでも足せる

## 検討した他の選択肢

### 最小限 + PDF 印刷

印刷用 CSS 30 行程度で「成果物を人に渡す」ところまで担保できる。

**却下理由**: 追加コストは小さいが、Phase 1 の主題から外れる。オンライン共有優先（[DR-0006](./0006-online-sharing-first.md)）のため PDF の必要性も低い。

### フル装備（発表者ビュー + 印刷）

**却下理由**: Harness の体裁を整える前にランタイムの実装量が先行し、目的と手段が逆転する。

## 帰結

- 発表者ビュー、ノート表示、PDF 出力は Phase 1.5 以降の Issue として起こす
- `notes` の受け取り口だけは最初から作る
- URL には現在のスライドに加えて Fragment の段階も含める（`#/3/2` の形）。measure が全段階を巡回できるようにするため（[DR-0011](./0011-lint-and-measure.md)）
