# DR-0049: 部品の実装の有無は、カタログの登録表で判定する

- **状態**: 承認済み
- **日付**: 2026-09-21
- **関連**: [DR-0021](./0021-starter-contains-runtime-only.md), [DR-0035](./0035-layout-component-contract-shape.md), [DR-0042](./0042-design-catalog-as-separate-build-entry.md), [DR-0047](./0047-catalog-previews-rebuild-the-canvas-box.md)
- **実装**: `src/docs/components.ts`（`COMPONENT_PREVIEWS` / `previewFor`）, `src/docs/pages/Components.tsx`

## 文脈

`design/components/` には4つの部品契約があるが、実装は無い。部品のページは「契約にあるのに実装が無い」を画面上の穴として見せる場所で、その穴が埋まったかどうかが部品実装（#37）の受け入れ基準になる。

つまりカタログは、部品ごとに実装の有無を判定する必要がある。ところが**実装をどこへ置くかは #37 の決定事項で、まだ決まっていない。** [DR-0021](./0021-starter-contains-runtime-only.md) が「starter にはスライド機構のみ」と決めているため、`src/runtime/` から公開すると Baseline 条件へ部品が混入して実験の条件差が壊れる。#37 は別の置き場所を決めることになる。

判定の方法を先に決めると、置き場所の決定をカタログが縛る。

## 決定

### 1. カタログは、契約名から引く登録表を持ち、登録が無ければ未実装とする

`src/docs/components.ts` の `COMPONENT_PREVIEWS` が、契約名からプレビューを引く表を持つ。いまは空で、4部品すべてが未実装として表示される。**これが正しい状態である。** #37 は部品を実装したら、ここへ契約名で登録する。

実装のファイルやクラス名を探しに行かない。探す先を決めることが、置き場所を決めることになるからだ。

### 2. 未実装は空欄ではなく「未実装」と書いて出す

枠だけを出さない。空欄だと「まだ描画していない」のか「実装が無い」のかが読み手に伝わらず、このページの役目が消える。

### 3. 判定はカタログに閉じ、`pnpm design:check` の検査項目にはしない

Issue #36 の非スコープに従う。実装の有無を契約として検査するのは、契約を1つ増やす判断であり、必要になった時点で別途決める。

### 4. 登録表を引く関数は、表を引数で受け取る

`previewFor(name, previews)` は既定値を持たない。呼び出し側は毎回どの表を見るかを書く。

## 理由

- **置き場所の決定を #37 に残す。** 実装を探しに行く判定は、探す先（CSS クラス名の規約、モジュールのパス）を先に決めることと同じだ。#37 は DR-0021 の条件差を壊さない置き場所を選ぶ必要があり、その選択肢をカタログが減らしてはいけない
- **登録表は、実装が増える側の手間が最小になる。** #37 は実装を書いて1行登録するだけでよい。探しに行く判定だと、実装の置き方が判定の期待と合っているかまで気にすることになる
- **「未実装」と書くことが、このページの成果物である。** 契約と実装の差を見せるために作るページなので、差が差として読めなければ作った意味が無い
- **既定値にすると、ページ側が「どの表を見ているか」を書かずに済んでしまう。** 既定値の引数は、呼び出し側が明示すれば上書きできる——道が塞がるわけではない。塞がるのは**読み手の側**だ。省略された呼び出しは、関数の宣言まで辿らないと何を見ているか分からない。加えて、省略するとモジュールの束縛をそのまま読むので、テストが差し替えた表が反映されない。実際この PR では、既定値にしていたために「登録があるときの見え方」を見るテストが、差し替えたはずの表ではなく空の表を読んで落ちた
- **登録表が空のままでは、実装がある側の枝が一度も実行されない。** 「未実装と出る」ことだけが確かめられ、登録があるときの見え方は #37 まで誰も見ないことになる。表を差し替えられる形にして、いまテストで踏む

## 検討した他の選択肢

### 契約名に対応する CSS クラスが、CSS ファイルに在るかを見る

[DR-0047](./0047-catalog-previews-rebuild-the-canvas-box.md) がレイアウトのプレビューで取った形（`design/layout.css` を読み込んで契約の `classes` を当てる）と揃う。レイアウト契約は `classes` を持つので、実装との対応を契約から引ける。

**却下理由**: 部品契約は `classes` を持たない（[DR-0035](./0035-layout-component-contract-shape.md)）。クラス名を決めるのはカタログ側になり、それは部品の実装の形を先に決めることと同じだ。加えて、#37 が React コンポーネントとして実装すると決めた場合、この判定は永久に「未実装」を返し続ける。

### 実装のモジュールを動的 import して、読めたかどうかで判定する

置き場所を1箇所決めれば、登録を書き足す手間が要らない。

**却下理由**: 置き場所を決め打つことそのものが却下理由に当たる。加えて `eslint.config.js` が、引数がリテラルでない `import()` をカタログで禁じている（[DR-0042](./0042-design-catalog-as-separate-build-entry.md)）。組み立てたパスの `import()` は lint が読めず、ビルドエントリの境界検査を素通りするからだ。

### 実装の有無を契約（`design/components/*.json`）に書く

正本が持つ情報になり、`pnpm design:check` で検査できる。

**却下理由**: 実装の有無は契約ではなく、いま何ができているかという状態である。契約に書くと、実装したのにフラグを直し忘れた状態が「契約違反」として現れる。Issue #36 も非スコープに挙げている。

## 帰結

- #37 は部品を実装したら `COMPONENT_PREVIEWS` へ契約名で登録する。登録を忘れると、カタログは実装済みの部品を未実装と表示し続ける。これは機械では捕まらない
- `previewFor` が全契約について `null` を返すこと（＝全部未実装）をテストが固定している。**#37 が `COMPONENT_PREVIEWS` へ登録するとこのテストは落ちる。** 落ちる契機は登録であって実装ではない。実装しただけで登録を忘れた状態は、上の帰結のとおり機械では捕まらない。落ちたときに「登録が入った」のか「登録表が壊れた」のかを人が判断する
- 登録表のキーが契約名と一致することは `components.test.ts` が見る。キーを綴り誤ると、実装済みの部品が「未実装」と表示され続け、型検査も lint も通る
- 契約の文言がカタログのソースへ書き写されていないことは、`src/docs/pages/no-contract-prose.test.ts` が `src/docs` 配下の実装すべてと、layout / component の全契約についてまとめて見る。ページごとにテストを置く形は取らない——ページを足した人が書き忘れた時点で守備範囲の外へ出るからだ
- **ページを足すときは、この検査へ何も書き足さなくてよい。** 対象のファイルは glob で取る。**ただし契約の種類を足すときは、`CONTRACT_PROSE` へ列挙を1行足す必要がある。** 自動で入るのは既存の種類の中身が増えたときだけだ
- **判定は1つの見方では行わない。** 画面に出る文字を変えずに文言を分断する書き方が何通りもあり、どの見方にも素通りする形が残るからだ。ソースを3つの見方——素のソース、JSX の式コンテナを落としたソース、文字列リテラルの静的に決まる部分——へ直し、そのいずれかに契約の文言が現れたら複製とする。行の折り返し・`'A' + 'B'` の連結・`${''}` の挿入・JSX の地の文を `{''}` で割る形が、これで塞がる。**見方を1つに絞る変更をするときは、どの形が素通りするようになるかを先に確かめること**——この PR では、静的な取り出しへ一本化した結果、JSX の地の文が丸ごと検査の外へ出た
- 契約の読み込み手順（`import.meta.glob` の結果をパス順に並べ、0件なら例外を投げる）は `src/docs/contracts.ts` の `contractsFrom` に一元化し、契約の種類が増えてもここを通す。`import.meta.glob` の呼び出し自体は各読み込み口に残る。Vite がビルド時にパスを静的に読む必要があり、引数で受け取る形にすると解決できない
- カタログが `src/runtime/` を参照できない制約（[DR-0042](./0042-design-catalog-as-separate-build-entry.md)）は変わらない。#37 が部品を `src/runtime/` へ置く選択をした場合、カタログは登録できない。その意味でこの決定は、#37 の置き場所に1つだけ条件を課している——**カタログから参照できる場所であること**
