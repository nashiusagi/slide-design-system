# DR-0046: 正本の複製は散文まで機械検査の対象にする

- **状態**: 承認済み
- **日付**: 2026-09-12
- **関連**: [DR-0009](./0009-five-layer-contract.md), [DR-0024](./0024-decision-records-not-adr.md), [DR-0028](./0028-single-check-entry-point.md), [DR-0033](./0033-derived-values-are-generated-and-checked.md), [DR-0044](./0044-bypass-fixtures-required.md)
- **実装**: `scripts/check-canonical-duplication.mjs`
- **正本**: 検査が読む値と一覧は `design/tokens.json` / `design/rules.json` / `design/layouts/` / `design/components/`。例外は `scripts/canonical-duplication-allowlist.json`

## 文脈

[指摘ログ](../review_log.md)で最も体積が大きい塊は「正本に置いた値・構造が、正本を参照できない場所へ写し取られた」ことだ（`contract/design-data-duplicated` ほか4カテゴリ、通算26回、初出 PR #13、最終 PR #51）。

26回とも人のレビューが見つけた。見つけられたということは、26回とも書かれてしまったということでもある。書いた側は複製だと思っていない。理由は毎回「読み手に親切だから」「ここにも無いと分からないから」で、もっともらしい。**もっともらしい違反は、人の注意では止まらない。**

[DR-0033](./0033-derived-values-are-generated-and-checked.md) は「導出値は生成し、再計算と突き合わせる」ことを決めた。しかし散文（`README.md` / DR / `SKILL.md` / カタログのコード）は生成できない。生成できない場所は、これまで人のレビューだけが見ていた。

## 決定

**正本の値と一覧が散文へ現れることを機械検査の対象にする。** `scripts/check-canonical-duplication.mjs` を `pnpm canonical:check` として `pnpm check` の静的検査段へ置く（[DR-0028](./0028-single-check-entry-point.md)）。

検査は3つの決めごとで成り立つ。

**1. 集める先は正本そのもの。** 検出する値・一覧をスクリプトへ列挙しない。トークンの値、`design/rules.json` の閾値、layout / component の名前と `allowedIn` の対応は、すべて実行時に正本を読んで組み立てる。正本が変われば検出対象も変わる。

**2. 一致の判定は「値らしい形」で行う。** 散文には正本と無関係な数字が現れる（「Phase 1.5」「3 周」）。そのままの数値一致では誤検出が支配的になり、検査が無視される。判定する形は3つに絞る。

- 単位付き（`13px` / `77%` のように、数値に単位が続く形）
- インラインコード（`` `13` `` のように、コード記法だけで置かれた値）
- キャンバス寸法の対（`<幅>x<高さ>`）

文字列の値（色・書体・影）は形を問わず一致で見る。十分に特徴的で、偶然一致しないからだ。

**3. 一覧の複製は順序を問わずに見る。** 正本の一覧（layout 名、component 名、ルールID、`allowedIn` の対応）の項目が、同じ表・箇条書きの中に1行1件で2件以上並べば複製として報告する。1行にその一覧の全項目が並ぶ形も報告する。

例外は `scripts/canonical-duplication-allowlist.json` に `path` / `target` / `reason` で登録する。**`reason` が無い、または短すぎるエントリは検査が落ちる。** 使われていないエントリも落ちる。

`docs/reviews/` は走査しない。レビュー記録は過去の指摘を引用するために値を含むのが正常であり、書き換えない履歴だからだ。

## 理由

- **26回のうち26回を人が見つけた、という事実は自動化の根拠として十分に強い。** 同じ判断を人が繰り返す場所は、機械が持つべき場所である
- **集める先を正本にすると、検査自身が複製にならない。** 値をスクリプトへ列挙すると、この検査こそが `contract/design-data-duplicated` の最新の実例になる
- **「値らしい形」に絞るのは、検査を無視されないため。** 誤検出が多い検査は、例外登録で骨抜きにされるか、実行されなくなる。塞げていない形（単位もコード記法も伴わない裸の数値）は既知の抜け道として帰結に書く
- **順序を問わないのは、並べ替えで素通りさせないため。** Issue #42 は「同順で並ぶ」形を挙げているが、順序を要求すると行を入れ替えるだけで抜けられる。順序を問わない判定は同順の場合を含む
- 例外に理由を必須にするのは、「もっともらしい理由」を書き残させるため。理由が書かれていれば、次のレビューがその理由自体を検査できる

## 検討した他の選択肢

### 値の一致をそのまま（形を問わず）見る

抜け道が最も少ない。

**却下理由**: `design/tokens.json` の `space` は 4 / 8 / 12 ... という素の整数で、散文のあらゆる数字と衝突する。誤検出が本物を埋め、例外リストが数百行になる。塞ぎ方を強くした結果として検査が使われなくなるのでは、塞いでいない。

### 検出する値をスクリプトの定数として列挙する

形ごとに細かく調整でき、誤検出を個別に潰せる。

**却下理由**: 正本の値をスクリプトへ書き写すことになる。この検査が禁じている行為そのものであり、正本を直したときに検査だけが古い値を見る。

### 既存の `checkSkillNoDesignDataDuplication`（`scripts/validate-design.mjs`）を拡張する

新しいスクリプトを増やさない。

**却下理由**: あちらが見ているのは `skills/slide-harness/SKILL.md` 1ファイルに対する**文章**の複製（layout の役割説明、rule の description、`DESIGN.md` の行）で、判定の性質が違う。同じ関数に両方を入れると、走査対象と判定形式の組み合わせが増えて守備範囲が読めなくなる（`inspection/rule-scope-inconsistent`）。**値と一覧は新しい検査、文章は既存の検査**と分ける。

### 正本の宣言を機械可読な1ファイルへ集約する

`contract/source-of-truth-ambiguous`（通算5回）にも同時に効く。

**却下理由**: この検査が要るのは「どの値が正本にあるか」であって、「どのファイルが正本か」の宣言ではない。集約ファイルを作れば `README.md` の正本表と二重管理になり、本 DR が潰そうとしている複製をもう1つ増やす。`source-of-truth-ambiguous` は別の Issue で扱う。

## 帰結

- 検査を `pnpm check` の `design:check` の直後に置く。正本を読むだけで走り、ビルド出力を要さない（[DR-0028](./0028-single-check-entry-point.md)）
- 走査対象は `README.md` / `DESIGN.md` / `docs/**/*.md`（`docs/reviews/` を除く）/ `.claude/skills/**/*.md` / `skills/**/*.md` / `src/docs/**`。対象の一覧はスクリプトが持ち、他へ写さない
- **裸の数値（単位もインラインコードも伴わない形）は検出しない。** 「コントラスト比は 4.5 以上」と書く形は素通りする。塞ぐには文脈語の辞書が要り、辞書は正本の外に置く新しい複製になる。この抜け道は既知として残す
- 例外を足すときは `reason` に「なぜ正本を参照できないのか」を書く。参照できるのに書き写しているなら、例外ではなく修正である
- 正本に値・一覧を足すと検出対象が自動で増える。既存の散文が落ちたときは、まず直す。直せないときだけ例外へ登録する
- `docs/reviews/` を除外している以上、レビュー記録の中の値は誰も検査しない。レビュー記録は履歴であり、そこから値を写す読み手を想定しない
