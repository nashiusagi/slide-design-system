# DR-0040: audit の API キー・token 検査は、主要ベンダーの既知形式 + 汎用の変数代入パターンに限る

- **状態**: 承認済み
- **日付**: 2026-09-10
- **関連**: [DR-0023](./0023-public-repo-with-audit.md)
- **正本**: `scripts/audit-public-data.mjs`（`STATIC_LEAK_PATTERNS` の実際のパターン一覧）

## 文脈

[DR-0023](./0023-public-repo-with-audit.md) は `scripts/audit-public-data.mjs` の役割を「置換漏れの文字列検査」とだけ定め、対象を絶対パス・OS ユーザー名に限っていた。Issue #11 の完了条件は「API キー・token らしき文字列パターンも検査対象に含む」を明示的に要求しており、DR-0023 が定めていなかった検査対象が実装で追加されることになった。

どの形式を検出するか、どんな閾値（文字数）を置くかは、それ自体が判断を要する（他の形式を選ぶ余地があった）。

## 決定

`scripts/audit-public-data.mjs` は次のパターンを検査する。

- 主要ベンダーの既知の鍵/トークン形式（OpenAI・Anthropic・GitHub・AWS アクセスキーID・Slack）
- 上記に当てはまらない秘密情報を拾うための汎用パターン: `api_key` / `secret` / `access_token` / `password` のような変数名らしき文字列への、16文字以上の値の代入

いずれも「それらしい形」に一致した時点で検査対象にする。実際に有効な鍵かどうかは判定しない（誤検知は許容し、見逃しを避ける）。

## 理由

- **このプロジェクトが実際に使う・生成過程で触れる可能性があるベンダー**（Claude Code が使う Anthropic、リポジトリ操作に使う GitHub、比較対象として触れうる OpenAI）を優先し、加えて広く知られた形式（AWS・Slack）を含めることで、実装コストを抑えつつ主要な漏洩経路をカバーする
- 汎用パターン（変数名 + 長い代入値）を足すのは、上記の固定形式に一致しない秘密情報（社内システムのトークン等）を取りこぼさないため。閾値は16文字とし、短い設定値（`"true"` 等）を誤検知しない程度に絞った
- 外部の secret-scanning ツール（gitleaks、trufflehog 等）を導入する案より、依存を増やさずこのリポジトリの他のスクリプトと同じ書き方（プレーンな Node、DR-0020）に揃えられる

## 検討した他の選択肢

### 外部の secret-scanning ツールを導入する

パターンの網羅性・保守を専門ツールに任せられる。gitleaks 等は業界標準のパターン集を持つ。

**却下理由**: 新しい外部ツール（Node の devDependency では済まないバイナリ）を `pnpm check` の経路に組み込む必要があり、Issue #11 のスコープに対して過剰。将来パターンの不足が実際に問題になったら検討する。

### 汎用パターンだけにし、ベンダー別の形式を持たない

実装が単純になり、パターンの保守が要らない。

**却下理由**: `sk-...` のような接頭辞だけの短い文字列は「変数への代入」という形を取らないログ出力（例外メッセージにそのまま埋め込まれる等）でも漏れうる。ベンダー別の形式を持つ方が、代入の形を取らない漏洩も拾える。

### 有効な鍵かどうかを外部 API へ問い合わせて確認する

誤検知が減る。

**却下理由**: DR-0020（スクリプトは AI を起動しない）と同じ精神で、audit も外部ネットワークアクセスを持たない静的な検査に留める。誤検知は人が最終判断する前提（DR-0023）なので、機械側で精度を上げる必要性が低い。

## 帰結

- 新しいベンダーの形式を足す、閾値を変えるといった変更は、この DR の「決定」を更新して行う
- パターンの実体（正規表現そのもの）はこの DR に複製しない。`scripts/audit-public-data.mjs` の `STATIC_LEAK_PATTERNS` を正本とする
- 誤検知（実際には秘密情報でない文字列がパターンに一致する）が実運用で頻発した場合は、閾値の調整または対象パターンの絞り込みを検討する
