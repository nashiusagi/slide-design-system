# DR-0031: ページ送りは → ← Space とクリックで行い、履歴を積まない

- **状態**: 承認済み
- **日付**: 2026-09-07
- **関連**: [DR-0004](./0004-phase-1-runtime-scope.md), [DR-0029](./0029-position-in-url-and-explicit-fragment-index.md), [DR-0011](./0011-lint-and-measure.md)

## 文脈

[DR-0004](./0004-phase-1-runtime-scope.md) は Phase 1 のランタイムを「スケーリングと URL 同期のみ」と決めたが、操作そのものは決めていない。Issue #3 の本文に「キーボード（→ ← Space）とクリックでの移動」とあるだけで、Issue はマージ後に読まれない。

もう一つ、URL を現在位置の表現にする（[DR-0029](./0029-position-in-url-and-explicit-fragment-index.md)）と決めた以上、ページ送りが**ブラウザの履歴を積むかどうか**を決める必要がある。積むなら戻るボタンが 1 手前のスライドへ戻り、積まないなら戻るボタンはデッキの外へ出る。

## 決定

- 進む — `→`、`Space`、デッキ上のクリック
- 戻る — `←`
- `Alt` / `Ctrl` / `Meta` を伴うキー入力は無視する
- 端では止まる。最後のスライドの最終段階で進んでも、最初のスライドで戻っても何も起きない
- ページ送りは**履歴を積まない**（`history.replaceState` で URL を書き換える）。ブラウザの戻るボタンはデッキの外へ出る

## 理由

- `Space` を「進む」に割り当てるのは、発表中に手元を見ずに押せるキーだから。プレゼンリモコンの多くも `Space` か `→` を送る
- クリックで進めるのは、キーボードが使えない環境（タブレット、他人の PC）でも送れるようにするため。戻る操作をクリックに割り当てないのは、誤操作の被害が非対称だから。1 枚進みすぎるのは戻せばよいが、右クリックや二本指クリックに戻るを割り当てると環境ごとに挙動が割れる
- 修飾キー付きを無視するのは、`Ctrl`+`→` などがブラウザやウィンドウマネージャの操作だから。それを奪うと発表中に別のことができなくなる
- 履歴を積まないのは、戻るボタンが「1 手前のスライド」ではなく「1 手前の**操作**」を辿ることになるから。段階を 3 つ出してから戻ると、スライドを戻るのに 4 回押すことになる。`←` が既にその役目を持っている

## 検討した他の選択肢

### `pushState` にして、ブラウザの戻るをスライドの戻るにする

戻るボタンが直感に合う。スマートフォンのスワイプバックでも戻れる。

**却下理由**: 履歴が操作の回数だけ伸びる。段階表示を多用したデッキでは、発表を終えて元のページへ戻るのに何十回も戻る必要が出る。[DR-0006](./0006-online-sharing-first.md) の想定（リンクを渡して見てもらう）では、閲覧者が「来たページへ戻れない」方が困る。

### `Space` を「戻る」に割り当てる（`Shift`+`Space` を進むに）

一部のドキュメントビューアの慣習に合う。

**却下理由**: プレゼンの慣習と逆で、リモコンが送るキーとも合わない。

### スワイプとキーボードショートカット一式（Home / End / 数字キー）を持つ

実用上は便利。

**却下理由**: [DR-0004](./0004-phase-1-runtime-scope.md) が切ったスコープの外。Phase 1 で証明したいのは機械判定であって操作性ではない。後から足すのは容易で、足しても既存の URL 表現は変わらない。

## 帰結

- 操作を増やすときはこの DR を更新する。増やしても [DR-0029](./0029-position-in-url-and-explicit-fragment-index.md) の URL 表現は変わらないので、measure（[DR-0011](./0011-lint-and-measure.md)）への影響は無い
- 履歴を積まないため、measure は戻る操作ではなく URL の組み立てで巡回する。これは [DR-0029](./0029-position-in-url-and-explicit-fragment-index.md) の帰結と同じ前提に立つ
- 発表者ビュー（Phase 1.5）を足すときは、別ウィンドウ間の位置同期をどう持つかを改めて決める。履歴を使わない以上、`localStorage` か `BroadcastChannel` になる
