# DR-0059: セルフチェックの `済` は Ready 化時点の差分だけを保証し、効果は1周目の指摘で測る

- **状態**: 承認済み
- **日付**: 2026-10-11
- **関連**: [DR-0052](./0052-review-loop-third-exit.md), [DR-0053](./0053-review-coverage-recorded.md), [DR-0057](./0057-self-check-before-ready.md)

## 文脈

[DR-0057](./0057-self-check-before-ready.md) は Ready 化の前に読み返す段を置き、その効果を `docs/review_log.md` のレビュー履歴表の「セルフチェック」列が `済` の PR で測ると決めた（決定7）。

[PR #72](https://github.com/nashiusagi/slide-design-system/pull/72) のレビュー3周目で、**その `済` が何を保証しているかが実態と合っていない**と指摘され、打ち切りで持ち越した（[#73](https://github.com/nashiusagi/slide-design-system/issues/73) / [#76](https://github.com/nashiusagi/slide-design-system/issues/76)）。

- **内容が誤っていても `済` になる。** `済` の判定（`.claude/skills/issue-workflow/references/self-check.md` の「この段を通した PR の数え方」）は手続きだけを見る。PR #72 自身が、セルフチェックに書いた参照が実在せず、訂正したはずの修正がファイルに入っていなかったのに `済` と記録されている
- **Ready 化より後の差分を、誰も自己点検していない。** セルフチェックは Ready 化の前に1回書くだけだ。PR #72 では、差分のほぼ半分が Ready 化より後の review-fix 側にあった

一方で DR-0057 決定7 の分子は、その PR の**全周**で出た指摘を数えている。基準値も同じで、`docs/review_log.md` の累計（1 PR につき全周を通して1回）から出した値だ。**`済` が見た範囲（Ready 化時点の差分）と、測定が数える範囲（全周の差分）が食い違っている。** 指摘が減らなかったとき、それが「段が効かない」からなのか、「段が見ていない差分で指摘が出た」からなのかを区別できない。

## 決定

### 1. 枠は問い直さず、その中で射程を揃える

DR-0057 決定7 の枠——`済` の PR を母数にして、レビューの指摘数で段の効果を測る——はそのまま残す。**枠そのものを問い直すのは、DR-0057 決定7 の最初の測定を経てからにする。**

### 2. `済` が保証するのは、Ready 化時点の差分について手続きを踏んだことだけ

`済` は「**Ready 化の時点の差分について、`self-check.md` の数え方を満たすコメントが Ready 化より前に出ている**」ことを意味する。それ以上は保証しない。

- **書かれた内容が正しいことは保証しない。** 正しさを判定するのは、レビューと、その結果を数える測定（決定3）だ
- **Ready 化より後の差分は対象外。** review-fix の差分に追加のセルフチェックは求めない

判定の条件そのもの（DR-0057 決定4・決定6、`self-check.md` の数え方）は変えない。変えるのは、その判定が何を意味すると読むかだけだ。

### 3. 測定は1周目の指摘だけを数える

DR-0057 決定7 の分子（対象8カテゴリの計上回数）は、**その PR の1周目のレビューで出た指摘に限る。** 1周目のレビューが見るのは Ready 化時点の差分で、`済` が保証する範囲（決定2）とちょうど重なる。数え方（1つのカテゴリは1つの PR につき1回）は `docs/review_log.md` と同じにする。

「1周目」は `issue-workflow` 手順5 が数える最初の周を指す。1件も結果が返らずやり直した回は含めない。

**1周目に観点が絞られていた、あるいは一部の観点が結果を返さなかった PR は、母数から除く。** 返らなかった観点の指摘は数えようがなく、分子が実際より小さく出る。立った観点はレビュー記録が持つ（[DR-0053](./0053-review-coverage-recorded.md)）。確かめられないなら母数に入れない——申告ではなく記録で決める（[DR-0052](./0052-review-loop-third-exit.md)）。

### 4. 基準値も同じ射程で数え直す

比べる相手の基準値も、**1周目の指摘だけ**で数え直す。母集団は、DR-0057 導入時点の基準値を出したときと同じ PR（PR #72 のマージ直前の `docs/review_log.md` のレビュー履歴表にある行）にする。全周の累計から出した今の基準値と、1周目だけの分子を比べると、分子が構造的に小さく出て、段が効いたように見えてしまう。

**決定3 の除外（観点が欠けた PR を除く）は、基準値の側には当てはめない。** 立った観点の記録は [DR-0053](./0053-review-coverage-recorded.md) より前の PR には無く、当てはめると母集団の大半が確かめられなくなる。この非対称は、基準値の側にだけ「観点が欠けて指摘が少なく出た周」が混ざりうるもので、**段の効果を小さく見せる向きにしか働かない。** 効果を過大に見積もる向きではないので許容する。最初の測定で基準値を下回らなかったときは、ここも疑う。

1周目をレビュー記録からどう切り出すかの手順は、決定の外に置く（帰結）。

### 5. 「`済` なのに内容が誤っていた」PR は特別扱いしない

PR #72 のように、`済` でありながらセルフチェックの内容が誤っていた PR も、**そのまま母数に入れ、1周目の指摘を分子に数える。** 誤りを見逃した分は1周目の指摘として現れ、「段が効かなかった1本」として測定に出る。それが、この段の効果として測るべきものだ。

除外する列や、訂正された回数を数える列は設けない。PR #72 自身は、DR-0057 決定7 の起点（PR #72 の次の PR から）により母数の外にある。

## 理由

**測定は、手続きではなく結果を数えている。** DR-0057 決定7 の分子はレビューで出た指摘の数だ。`済` が手続きしか保証しなくても、内容が誤っていればその誤りは指摘として分子に現れる。PR #72 の3周目は「手続きを測って効果を測ろうとしている」と枠そのものを疑ったが、効果を測っているのは分子のほうで、`済` は母数を選ぶ条件にすぎない。**壊れていたのは枠ではなく、母数を選ぶ条件の射程と、分子を数える射程のずれだ。**

**ずれは、分子の射程を `済` に合わせれば閉じる。** 1周目のレビューは Ready 化時点の差分を見る。その周の指摘だけを数えれば、`済` が見た範囲と測定が数える範囲が一致する。新しい列も、PR ごとに書く手順も増えない。レビュー記録は周ごとに節が分かれており、1周目の指摘は記録から読める。

**枠の問い直しは、測定の結果を見てからでよい。** 射程を揃えれば、測定は「段が効いたか」を区別できる形になる。最初の測定でも基準値を下回らなければ、そのときに項目・置き場所・枠そのものを見直せる（DR-0057 決定7 の後半）。いま測る前に枠を変えると、変える前の枠が効いたかどうかが永久に分からない。

## 検討した他の選択肢

**枠を問い直す（決定1 の代案）。** PR #72 の3周は、判定を具体化するたびに一段深い穴が出た。手続きで `済` を判定する設計自体が限界だという見方には筋がある。採らないのは、DR-0057 決定7 の測定を一度も経ていないからだ。上の「理由」のとおり、射程さえ揃えば測定は効果を区別できる。

**`済` の意味を縮めるだけで、測定は全周のまま数える（Issue の案 (a) の単独）。** 文言を直すだけで済む。採らないのは、`済` と測定の射程のずれがそのまま残るからだ。Ready 化より後の差分で出た指摘まで分子に入り、段の効果と区別できない。

**review-fix が増えたら追加のセルフチェックを求める（案 (b)）。** `済` の射程を全周へ広げられる。採らないのは、手順が重くなるうえ、「一定量」の決め方が `writing/ambiguous-criterion` を招くからだ。DR-0057 の目的の一つは周の消費を減らすことで、レビューのたびに書く段を足すのはその逆を向く。

**`済` はそのままで、内容がレビューで訂正された回数の列を足す（案 (c)）。** 「`済` なのに効かなかった」を区別できる。採らないのは、決定5 のとおり、その区別は1周目の指摘数に既に現れるからだ。PR #72 の3周では、列を足すたびに「書式の正本に無い」と指摘され続けた。

**「`済` なのに内容が誤っていた」PR を母数から除く（決定5 の代案）。** `済` の PR を「ちゃんと読み返した PR」に近づけられる。採らないのは、それが段の失敗を測定から取り除くことになるからだ。読み返したつもりで読み返していない、という失敗こそこの段が防ごうとしているもので、除けば効果を過大に見積もる。内容の誤りを誰が判定するかという、新しい申告の入口も開く。

## 帰結

- [DR-0057](./0057-self-check-before-ready.md) の決定7 のうち、**分子（計上回数）と基準値を数える範囲**をこの DR が置き換える。母数の取り方・起点・5本で測ること・下回らなければ見直すことはそのまま有効だ。DR-0057 の状態欄・決定7・帰結へその旨を書く
- DR-0057 の決定4・決定6（`済` の判定条件）は置き換えない。何を保証するかを決定2 が限定するだけだ
- 定義を持つ3箇所——`.claude/skills/issue-workflow/references/self-check.md` の数え方、`docs/review_log.md` の「セルフチェック」列と基準値、`.claude/skills/pr-review/references/review-log-format.md` の更新の手順——を、この DR へ揃える作業は [#77](https://github.com/nashiusagi/slide-design-system/issues/77) が受け持つ。1周目をレビュー記録から切り出す手順と、基準値の数え直し（決定4）もそこに含む。**揃うまでは、`docs/review_log.md` の基準値（全周）を DR-0057 決定7 の比較に使わない**
- 1周目の観点が欠けた PR は母数から除く（決定3）。除いた PR が多ければ5本たまるのが遅れる
