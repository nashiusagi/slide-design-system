# DR-0024: 決定記録は `docs/decisions/` に置き、「DR」と呼ぶ

- **状態**: 承認済み
- **日付**: 2026-09-06
- **関連**: [DR-0007](./0007-north-star.md), [DR-0008](./0008-accent-hue-purple.md), [DR-0012](./0012-min-font-size.md)

## 文脈

意思決定を「理由」と「検討した他の選択肢」つきで記録することは決まっていた。当初は ADR（Architecture Decision Record）という呼称を想定していたが、記録対象を並べると問題が二つ見えた。

一つ目。ADR は本来「アーキテクチャ的に重要な決定」を対象とする。しかし記録したい決定には、北極星（[DR-0007](./0007-north-star.md)）、アクセントの色相（[DR-0008](./0008-accent-hue-purple.md)）、`min-font-size` の閾値（[DR-0012](./0012-min-font-size.md)）といった、アーキテクチャではないデザインの決定が含まれる。

二つ目。それらのデザイン決定には既に正本がある。`DESIGN.md` と `tokens.json`、`rules.json` である。記録に値まで書けば二重管理になり、**このプロジェクト自身の原則（正本を一つに保つ、設計データを複製しない）に違反する**。

なお MADR は v3 で "Markdown **Architectural** Decision Records" から "Markdown **Any** Decision Records" へ改名しており、この問題は形式の本家も認めている。

## 決定

- ディレクトリは `docs/decisions/`、呼称は「決定記録（Decision Record / DR）」とする
- 形式は MADR に準拠し、各記録に「文脈 / 決定 / 理由 / 検討した他の選択肢と却下理由 / 帰結」を置く
- **デザインの値（色、閾値、スケール）は DR に複製しない。** DR には決定の要約・理由・却下した選択肢・正本へのリンクだけを書く

## 理由

- アーキテクチャに限らない決定を無理なく含められる
- 値の正本が 1 つに保たれる。値を変えるときは正本を編集し、DR は「なぜその水準か」の根拠として残る
- 理由と却下案は `DESIGN.md` に書きにくい。DR 側に置く価値がある

## 検討した他の選択肢

### `docs/adr/` で「ADR」のまま

最も広く通じる呼称で、他人への説明が不要。

**却下理由**: 記録対象と名前が合わない。厳密さを取った。

### 2 系統に分ける（仕組みは ADR、デザインは DESIGN.md の「決定と根拠」節へ）

境界が明確になる。

**却下理由**: 「あの決定はどちらに書いたか」を毎回考えることになる。

## 帰結

- 値を含む決定（[DR-0007](./0007-north-star.md) / [DR-0008](./0008-accent-hue-purple.md) / [DR-0012](./0012-min-font-size.md)）は `**正本**:` 行を持ち、値そのものは書かない
- 新しい決定は連番で追加する。既存の決定を覆す場合は、新しい DR を立てて旧 DR の状態を「置き換え済み」に変える
