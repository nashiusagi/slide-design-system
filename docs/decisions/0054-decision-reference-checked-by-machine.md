# DR-0054: DR の参照・索引・冒頭欄は機械で検査し、帰結の反映は人が読む

- **状態**: 承認済み
- **日付**: 2026-09-23
- **関連**: [DR-0024](./0024-decision-records-not-adr.md), [DR-0028](./0028-single-check-entry-point.md), [DR-0046](./0046-prose-checked-for-canonical-duplication.md)
- **実装**: `scripts/check-decisions.mjs`

## 文脈

決定記録まわりの指摘は、内容の是非ではなく「参照が壊れている／古い」ものが繰り返し出ている。[`docs/review_log.md`](../review_log.md) の累計で、`decisions/citation-points-to-wrong-file` が4回、`decisions/index-section-mismatch` が3回、`decisions/wrong-dr-citation` が4回、`decisions/citation-incomplete-after-rewrite`（本文を書き換えたが冒頭欄が古いまま）が3回、`decisions/consequence-not-followed` が11回。

DR は53本あり、相互に参照し、README・SKILL.md・スクリプトからも引かれている。参照の張り替えを人手で追い切るのは、本数が増えるほど無理になる。

**実害も出た。** [PR #60](../reviews/pr-60.md) では、`.claude/skills/pr-review/references/review-file-format.md` に足した DR リンク2本が1階層浅く、`.claude/docs/decisions/...` という存在しないパスを指していた。その2本は「なぜこの項目が必須なのか」の唯一の根拠で、辿れないまま `pnpm check` は緑だった。1周目のレビューで人が見つけている。

このリポジトリは「同じ指摘が何度も出るなら、機械検査へ昇格すべき」という方針を持つ（`.claude/skills/pr-review/SKILL.md`）。参照の実在・索引の整合・冒頭欄の書式は、意味を読まずに判定できる。

## 決定

### 1. 参照・索引・冒頭欄を `pnpm check` で検査する

`scripts/check-decisions.mjs` を置き、[DR-0028](./0028-single-check-entry-point.md) に従って `pnpm check` から呼ぶ。見るのは5つ。

- コードフェンスが閉じているか（決定3）
- 文書中の `DR-NNNN` 参照が実在するか
- **走査対象の中の相対 `.md` リンクが実在するか**（DR へのリンクに限らない）。あわせて、リンクテキストが `DR-NNNN` ならリンク先のファイル名の番号と一致するか
- 索引が全 DR を漏れなく登録し、節の中が番号の昇順か
- 冒頭欄（状態 / 日付 / 関連）が揃い、日付が `YYYY-MM-DD` で、関連が自分自身を指さず、関連・正本・実装に挙げた参照が実在するか

**見るのは `.md` だけだ。** 走査対象の根に `scripts/` や `design/` を挙げていても、
`.mjs` や `.json` の中の `DR-NNNN` は見ない。Markdown には「これは例だ」と印を付ける
手段——コードフェンス——があるが、コードやデータには無い。実際 `scripts/*.mjs` には
本物の引用（コメント）と偽番号（`check-decisions.test.mjs` の `DR-9999`）が同じ形で
並んでいる。区別するには別の取り決めが要り、それはこの Issue の仕事ではない。
**その結果、`.md` の外にある DR 参照は検査されない**——`scripts/` 配下の `.mjs` と
`design/` 配下の `.json` を再帰的に見て `DR-NNNN` の出現数を数えると、合わせて200を
超える。**正確な数は書かない。** この DR が挙げる数は判断の根拠になるのに、その数は
ファイルを1つ足すだけで動き、数え方（再帰するか、テストの偽番号を含むか）でも変わる。
再現できない数を根拠に据えない（`decisions/cited-tally-not-reproducible`）。広げるか
どうかは別の Issue で決める。

**索引の節の分類が内容と合うかは見ない。** 意味の問題なので、レビューの観点（決定記録との整合）が持つ。同じ理由で、実在する誤った番号の引用と、引用先の節がその内容を持つかも見ない。

走査対象は `docs/reviews/` を除く。レビュー記録は過去の指摘をそのまま引用するために古い番号・古いパスを含むのが正常で、かつ書き換えない履歴だからだ（[DR-0046](./0046-prose-checked-for-canonical-duplication.md) が同じ理由で外しているのに揃える）。

コードブロックとインラインコードの中身は見ない。書式サンプルには実在しない番号やパスが例として書かれる。あれは参照ではない。

### 2. `**正本**:` 行に実装コードを挙げることを、機械で禁じる

判定の軸は**拡張子**に取る。どの拡張子を実装コードとみなすかは判定の調整なので、一覧は `**実装**:` が指すスクリプトが持つ（[DR-0046](./0046-prose-checked-for-canonical-duplication.md) が下限の数値について採ったのと同じ扱い）。在り処を示したいときは `**実装**:` を使う。

**ディレクトリ指定（`src/runtime/` のような末尾スラッシュ）は落とさない。** 中の何を正本と呼んでいるかは読まないと分からないので、人の目に残す。同じ理由で、[DR-0046](./0046-prose-checked-for-canonical-duplication.md) が `**正本**:` 行で「走査する場所は同スクリプトの `SCAN_ROOTS`」と書いている形も落とさない——ファイル名ではなく識別子を指しており、機械では実装コードかどうか判定できない。**この2つが決定2 の穴で、埋めるには人が読む必要がある。**

この規則自体は [`docs/decisions/README.md`](./README.md) の「新しい決定を追加するとき」が既に書いている。決めたのは**判定の仕方**だ。値がコードの中にしか無い場合（[DR-0039](./0039-experiment-starter-checked-against-root-scaffold.md) の足場の一覧、[DR-0040](./0040-audit-secret-pattern-selection.md) のパターン一覧）も例外にしない。その2本はこの PR で `**実装**:` へ直した。

### 3. コードフェンスが閉じていないファイルは落とす

書式サンプルを検査から外すため、コードブロックの中身は捨てている。閉じ忘れがあると以降の行がすべて捨てられ、そのファイルの参照もリンクも見られないまま緑になる。**行を捨てる判断をした以上、捨てた範囲が意図どおりであることは検査側が保証する。**

### 4. 参照の双方向性は求めない

A が B を関連に挙げているのに B が A を挙げていない状態を、この検査は落とさない。

### 5. 「帰結」節の書式は変えない

`decisions/consequence-not-followed`（帰結に書いた内容が、それを通る手順へ反映されていない）は累計11回で、**文脈に挙げた決定記録まわりの5カテゴリの中では最多**だが、この検査では扱わない。帰結に「誰が / どのファイルが / いつ」を書かせる書式も導入しない。

## 理由

- **参照の壊れ方は、読めば分かるのに読まなければ通る。** だから機械の仕事だ。逆に「帰結が手順へ反映されているか」は意味の問題で、反映されたかどうかは手順の文を読んで判断するしかない
- **「これは例だ」の印があるのは Markdown だけだ。** だから `.md` に限る（決定1）。コードフェンスとインラインコードを外せば、残るのは本物の参照になる。コードやデータには対応する印が無く、`scripts/check-decisions.test.mjs` の `DR-9999` のような偽番号が、他のスクリプトのコメントにある本物の引用と同じ形で並ぶ。区別するには別の取り決めが要り、それを決めるのはこの DR ではない
- **リンクの階層は人が数えにくい。** `.claude/skills/pr-review/references/` から `docs/` へ戻るのは4階層で、1つ浅い書き方が隣のファイル（`pr-review/SKILL.md`）では正しい。PR #60 はまさにそこで間違えた。機械なら解決して確かめるだけで済む
- **双方向性を強制すると、参照の意味が壊れる。** 「この DR を読むならあちらも要る」という一方向の依存は正常だ（新しい DR が古い DR を前提にする形）。双方向を求めると、古い DR が新しい DR を知っている状態を作ることになり、追記が際限なく増える。**置き換えの関係だけは別で**、そちらは状態欄・該当箇所・帰結の3箇所へ書く規則が README にある（[DR-0052](./0052-review-loop-third-exit.md) / [DR-0053](./0053-review-coverage-recorded.md) が例）
- **帰結の書式を変えると、書ける内容が痩せる。** 「誰が / どのファイルが / いつ」の枠に収まらない帰結——「確認未了が続くようなら (b) の根本解が要るという信号になる」のような——が、枠に合わせて削られる。反映漏れを捕まえたいなら、枠ではなく**レビューの観点**（決定記録との整合）が見るべきものだ。実際そちらで毎回見つかっている
- **捨てた範囲が意図どおりであることを、捨てた側が保証する。** コードブロックを外すのは書式サンプルを参照とみなさないためだが、閉じ忘れがあると「何も書かれていないファイル」として静かに緑になる。緑が何も保証しない状態をファイル単位で作れるので、落とす（決定3）
- **値がコードの中にしかない場合も、正本とは呼ばない。** 呼べば、コードを書き換えた時点で DR ではなくコードが正しいことになる（README の理由そのまま）。`**実装**:` に注記を添えれば在り処は残る。値をコードの外へ出すべきかは別の判断で、この DR では決めない

## 検討した他の選択肢

### 帰結の反映も機械で検査する

**却下理由**: 累計11回（文脈の5カテゴリの中では最多）で効果は大きそうに見えるが、帰結の文と、それを反映すべき手順の文を突き合わせるには意味の理解が要る。文字列一致で近いものを探す形にすると、偽陽性で緑が信用できなくなる。**緑が何も保証しない検査は、無い方がましだ**（[DR-0044](./0044-bypass-fixtures-required.md) が bypass フィクスチャで同じ問題を扱っている）。

### 双方向の参照を強制する

関連の張り忘れを落とせる。`decisions/one-sided-coupling` は累計6回。

**却下理由**: 上の理由のとおり、一方向の依存は正常な形だ。落とすべきなのは「置き換えの関係が片方にしか書かれていない」場合で、それは状態欄の規則が扱う。関連欄すべてに双方向を求めると、正常な参照まで落ちる。

### 検査を `.md` の外と走査対象の外へ広げる

壊れた参照は `.md` に限らない。`scripts/` 配下の `.mjs` のコメントにも `design/` 配下の `.json` の `$comment` にも DR 引用があり、合わせて200を超える。

**却下理由**: 走査対象の中の相対 `.md` リンクは、DR を指すかどうかにかかわらず決定1 が既に見ている。広げないのは2方向で、どちらも**取り決めから決め直す必要がある**という理由だ。スコープ外だからではない——[Issue #45](https://github.com/nashiusagi/slide-design-system/issues/45) の目的の節は「DR は…README・SKILL.md・**スクリプトからも引かれている**」と書き、やることの節は「文書中の**すべての** `DR-00xx` 参照」と書いている。`.md` に限る文言は無い。

- **`.md` の外** — 決定1 のとおり「これは例だ」の印が無く、本物の引用と偽番号を区別する取り決めが要る
- **走査対象の外** — `docs/reviews/` を外す理由は決定1 が書いている。生成物（`node_modules` / `dist`）を外す理由は決定1 には無く、`**実装**:` が指すスクリプトの `SCAN_ROOTS` が持つ。覆すなら [DR-0046](./0046-prose-checked-for-canonical-duplication.md) と揃えて決め直すことになる

広げるなら別の Issue で。

### 拡張子ではなくディレクトリで実装コードを判定する

`scripts/` `src/` `packages/` の下を実装とみなす。

**却下理由**: `design/` に置かれた `.mjs`（もしあれば）を取りこぼす。拡張子の方が「コードかどうか」に直接対応する。

## 帰結

- `pnpm check` に `decisions:check` が入る。**ファイルを読むだけで走りビルド出力を要さないので、静的検査段（`canonical:check` の直後）に置く**（[DR-0028](./0028-single-check-entry-point.md) の帰結「どの段に入るかを併せて決める」）。存在しない DR を参照する、リンクの階層を間違える、索引へ登録し忘れる、冒頭欄を落とす、コードフェンスを閉じ忘れる——どれも `main` へ入る前に落ちる
- **この検査が緑でも、決定の中身が正しいことは保証しない。** 参照が実在するか、番号が一致するか、冒頭欄が書式を満たすかだけを見る
- この DR を根拠に `docs/review_log.md` の状態欄が5行変わる。決定1 により `wrong-dr-citation` / `citation-points-to-wrong-file` / `index-section-mismatch` が「一部」、決定4 により `one-sided-coupling` が「見送り」、決定5 により `consequence-not-followed` が「見送り」。`consequence-not-followed` と `one-sided-coupling` は引き続きレビューの観点（決定記録との整合）が持つ
- [DR-0039](./0039-experiment-starter-checked-against-root-scaffold.md) / [DR-0040](./0040-audit-secret-pattern-selection.md) の冒頭欄が `**正本**:` から `**実装**:` へ変わった。決定の内容は変えていない
- **`.md` の外にある DR 参照は検査されない。** `scripts/` 配下の `.mjs` と `design/` 配下の `.json` に、合わせて200を超える引用がある。決定1 のとおり、コードやデータには「これは例だ」の印が無いので区別の取り決めから決め直す必要があり、別の Issue として切れる
- 走査対象の外（生成物、`docs/reviews/`）へのリンク検査と、一般的な Markdown の構文検査は、この DR では決めない。**コードフェンスの対応だけは例外で、決定3 が扱う**——あれは一般的な構文検査ではなく、決定1 の参照検査が捨てた範囲を保証するためのものだ。[PR #60](../reviews/pr-60.md) で出た `code/unclosed-fence-swallows-trailing-prose`（閉じ忘れが地の文を呑み込む）は表示の問題で、そちらは別に切れる
