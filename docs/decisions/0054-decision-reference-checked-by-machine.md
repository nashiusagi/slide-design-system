# DR-0054: DR の参照・索引・冒頭欄は機械で検査し、帰結の反映は人が読む

- **状態**: 承認済み
- **日付**: 2026-09-23
- **関連**: [DR-0024](./0024-decision-records-not-adr.md), [DR-0028](./0028-single-check-entry-point.md), [DR-0046](./0046-prose-checked-for-canonical-duplication.md)
- **実装**: `scripts/check-decisions.mjs`

## 文脈

決定記録まわりの指摘は、内容の是非ではなく「参照が壊れている／古い」ものが繰り返し出ている。[`docs/review_log.md`](../review_log.md) の累計で、`decisions/citation-points-to-wrong-file` が4回、`decisions/index-section-mismatch` が3回、`decisions/wrong-dr-citation` が4回、`decisions/consequence-not-followed` が11回。

DR は53本あり、相互に参照し、README・SKILL.md・スクリプトからも引かれている。参照の張り替えを人手で追い切るのは、本数が増えるほど無理になる。

**実害も出た。** [PR #60](../reviews/pr-60.md) では、`.claude/skills/pr-review/references/review-file-format.md` に足した DR リンク2本が1階層浅く、`.claude/docs/decisions/...` という存在しないパスを指していた。その2本は「なぜこの項目が必須なのか」の唯一の根拠で、辿れないまま `pnpm check` は緑だった。1周目のレビューで人が見つけている。

このリポジトリは「同じ指摘が何度も出るなら、機械検査へ昇格すべき」という方針を持つ（`.claude/skills/pr-review/SKILL.md`）。参照の実在・索引の整合・冒頭欄の書式は、意味を読まずに判定できる。

## 決定

### 1. 参照・索引・冒頭欄を `pnpm check` で検査する

`scripts/check-decisions.mjs` を置き、[DR-0028](./0028-single-check-entry-point.md) に従って `pnpm check` から呼ぶ。見るのは4つ。

- 文書中の `DR-NNNN` 参照が実在するか
- DR へのリンクが実在し、リンクテキストの番号とリンク先のファイル名が一致するか
- 索引が全 DR を漏れなく登録し、節の中が番号の昇順か
- 冒頭欄（状態 / 日付 / 関連）が揃い、関連・正本・実装に挙げた参照が実在するか

走査対象は `docs/reviews/` を除く。レビュー記録は過去の指摘をそのまま引用するために古い番号・古いパスを含むのが正常で、かつ書き換えない履歴だからだ（[DR-0046](./0046-prose-checked-for-canonical-duplication.md) が同じ理由で外しているのに揃える）。

コードブロックとインラインコードの中身は見ない。書式サンプルには実在しない番号やパスが例として書かれる。あれは参照ではない。

### 2. `**正本**:` 行に実装コードを挙げることを、機械で禁じる

判定は拡張子で行う（`.mjs` / `.ts` / `.tsx` / `.js` / `.jsx`）。在り処を示したいときは `**実装**:` を使う。

この規則自体は [`docs/decisions/README.md`](./README.md) の「新しい決定を追加するとき」が既に書いている。決めたのは**判定の仕方**だ。値がコードの中にしか無い場合（[DR-0039](./0039-experiment-starter-checked-against-root-scaffold.md) の足場の一覧、[DR-0040](./0040-audit-secret-pattern-selection.md) のパターン一覧）も例外にしない。その2本はこの PR で `**実装**:` へ直した。

### 3. 参照の双方向性は求めない

A が B を関連に挙げているのに B が A を挙げていない状態を、この検査は落とさない。

### 4. 「帰結」節の書式は変えない

`decisions/consequence-not-followed`（帰結に書いた内容が、それを通る手順へ反映されていない）は累計11回で最多だが、この検査では扱わない。帰結に「誰が / どのファイルが / いつ」を書かせる書式も導入しない。

## 理由

- **参照の壊れ方は、読めば分かるのに読まなければ通る。** だから機械の仕事だ。逆に「帰結が手順へ反映されているか」は意味の問題で、反映されたかどうかは手順の文を読んで判断するしかない
- **リンクの階層は人が数えにくい。** `.claude/skills/pr-review/references/` から `docs/` へ戻るのは4階層で、1つ浅い書き方が隣のファイル（`pr-review/SKILL.md`）では正しい。PR #60 はまさにそこで間違えた。機械なら解決して確かめるだけで済む
- **双方向性を強制すると、参照の意味が壊れる。** 「この DR を読むならあちらも要る」という一方向の依存は正常だ（新しい DR が古い DR を前提にする形）。双方向を求めると、古い DR が新しい DR を知っている状態を作ることになり、追記が際限なく増える。**置き換えの関係だけは別で**、そちらは状態欄・該当箇所・帰結の3箇所へ書く規則が README にある（[DR-0052](./0052-review-loop-third-exit.md) / [DR-0053](./0053-review-coverage-recorded.md) が例）
- **帰結の書式を変えると、書ける内容が痩せる。** 「誰が / どのファイルが / いつ」の枠に収まらない帰結——「確認未了が続くようなら (b) の根本解が要るという信号になる」のような——が、枠に合わせて削られる。反映漏れを捕まえたいなら、枠ではなく**レビューの観点**（決定記録との整合）が見るべきものだ。実際そちらで毎回見つかっている
- **値がコードの中にしかない場合も、正本とは呼ばない。** 呼べば、コードを書き換えた時点で DR ではなくコードが正しいことになる（README の理由そのまま）。`**実装**:` に注記を添えれば在り処は残る。値をコードの外へ出すべきかは別の判断で、この DR では決めない

## 検討した他の選択肢

### 帰結の反映も機械で検査する

累計11回と最多なので、効果は大きい。

**却下理由**: 帰結の文と、それを反映すべき手順の文を突き合わせるには意味の理解が要る。文字列一致で近いものを探す形にすると、偽陽性で緑が信用できなくなる。**緑が何も保証しない検査は、無い方がましだ**（[DR-0044](./0044-bypass-fixtures-required.md) が bypass フィクスチャで同じ問題を扱っている）。

### 双方向の参照を強制する

関連の張り忘れを落とせる。`decisions/one-sided-coupling` は累計6回。

**却下理由**: 上の理由のとおり、一方向の依存は正常な形だ。落とすべきなのは「置き換えの関係が片方にしか書かれていない」場合で、それは状態欄の規則が扱う。関連欄すべてに双方向を求めると、正常な参照まで落ちる。

### リンクの検査を DR 以外のリンクへも広げる

壊れた相対リンクは DR に限らない。実際 PR #60 では書式ファイル同士のリンクも書き換えている。

**却下理由**: #45 のスコープは DR の参照・索引・書式で、文書全体のリンク検査は別の仕事になる（走査対象・除外・生成物の扱いを決め直す必要がある）。この検査は DR へのリンクだけを見る。広げるなら別の Issue で。

### 拡張子ではなくディレクトリで実装コードを判定する

`scripts/` `src/` `packages/` の下を実装とみなす。

**却下理由**: `design/` に置かれた `.mjs`（もしあれば）を取りこぼす。拡張子の方が「コードかどうか」に直接対応する。

## 帰結

- `pnpm check` に `decisions:check` が入る。存在しない DR を参照する、リンクの階層を間違える、索引へ登録し忘れる、冒頭欄を落とす——どれも `main` へ入る前に落ちる
- **この検査が緑でも、決定の中身が正しいことは保証しない。** 参照が指す先が実在し、番号が一致していることだけを見る
- `decisions/consequence-not-followed` は引き続きレビューの観点（決定記録との整合）が持つ。`docs/review_log.md` の状態欄には、機械化しない判断としてこの DR を記す
- [DR-0039](./0039-experiment-starter-checked-against-root-scaffold.md) / [DR-0040](./0040-audit-secret-pattern-selection.md) の冒頭欄が `**正本**:` から `**実装**:` へ変わった。決定の内容は変えていない
- 文書全体のリンク検査（DR 以外）と、Markdown の構文検査（コードフェンスの対応）は、この DR では決めない。[PR #60](../reviews/pr-60.md) で `code/unclosed-fence-swallows-trailing-prose` が出ており、同じ性質の仕事として別に切れる
