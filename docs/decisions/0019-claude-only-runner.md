# DR-0019: ランナーは Claude Code のみとし、`claude -p` を使わない

- **状態**: 承認済み
- **日付**: 2026-09-06
- **関連**: [DR-0020](./0020-scripts-do-not-invoke-ai.md), [DR-0014](./0014-baseline-comparison.md)

## 文脈

Atlas は `scripts/agent-runners/` に `codex.mjs` と `claude.mjs` を持ち、`--runner` で切り替えていた。複数モデルで回せると「契約の効果はモデルに依らない」と主張できる。

この環境を調べたところ、`claude` は導入済み（2.1.263）だが `codex` は未導入だった。また非対話実行（`claude -p`）については、トークン消費が読めないことと、Claude Code のサブエージェントで回したいという要望がある。

## 決定

Claude Code のみを対象とする。`claude -p` による非対話実行は行わず、**サブエージェントを明示的に 1 回ずつ起動して生成する**。

## 理由

- 実行回数が常に手動になるため、トークン消費が完全に見える
- サブエージェントは別コンテキストで走るため、baseline / harness のコンテキスト分離をきれいに行える
- `codex` が未導入であり、導入と認証の手間が Phase 1 の着手を遅らせる

## 検討した他の選択肢

### Claude Code + Codex 両方

モデル差によるぶれを見られる。

**却下理由**: `codex` 未導入。環境整備が先に入る。将来必要になったら DR を追加して runner 抽象を足す。

### `claude -p` による自動実行

スクリプトから一括で回せて再現性が高い。

**却下理由**: トークン消費が読めない。またサブエージェントで回したいという運用上の要望と合わない。

## 帰結

- **比較の公平性を運用で担保する必要がある。** 同じ `prompt.md`、同じ starter、同じ初期状態から起動することを手順として明記する
- スクリプトは AI を起動しない設計になる（[DR-0020](./0020-scripts-do-not-invoke-ai.md)）
- 生成は手動、検査と採点は自動という役割分担になる
