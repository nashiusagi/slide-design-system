- **場所**: `src/docs/docs.css.test.ts`:15（読み込み宣言を取り出す正規表現）

  ```js
  const css = "@import url('../../src/runtime/runtime.css');\n"
  [...css.matchAll(/@import\s+['"]([^'"]+)['"]\s*;/g)] // => [] （何も検出しない）
  ```

- **なぜ問題か**: この検査は「DR-0047 が却下した『`runtime.css` を読み込む』案が機械で止まる」ために1周目で新設したものである。`url()` 記法は Vite も PostCSS も等価に処理する正規の書き方なので、その形で書けば実際にバンドルへ取り込まれる一方、`IMPORTED` には現れない。**塞いだはずの抜け道を、形だけ塞いで実質は塞いでいない。**
- **失敗シナリオ**: `docs.css` へ `@import url('../../src/runtime/runtime.css');` を足すと、`pnpm lint` も `pnpm test` も緑のまま `src/runtime/` の CSS がカタログのバンドルへ入る。
- **提案**: 正規表現を `url()` と修飾子（メディアクエリ・`layer()`）に対応させるか、PostCSS の構文木で `@import` ノードを列挙する（[DR-0041](../decisions/0041-postcss-for-layout-class-check.md) が同じ理由で PostCSS を選んでいる）。

### should

#### `inspection/rule-has-bypass`（この PR で計上済み） — PostCSS の列挙が `@import` の大文字小文字違いで素通りする

- **場所**: `src/docs/docs.css.test.ts`:48-50（`walkAtRules('import', ...)`）
- **指摘した観点**: 検査ルールの実効性
- **累計**: この PR では2周目に計上済みのため、回数は増やさない
- **何が起きているか**: `walkAtRules` に文字列を渡すと `child.name === name` の完全一致になり、大文字小文字を区別する。CSS の at-rule キーワードは ASCII の大文字小文字を区別しないので `@IMPORT` も同じ宣言だが、この検査は拾わない。レビュアーが `docs.css` へ `@IMPORT '../../src/runtime/runtime.css';` を足して実測し、3件とも緑のまま通ることを確認した（確認後は復元済み）。
- **なぜ問題か**: 2周目で塞いだのは**パラメータ側**の記法（引用符 / `url()`）だけで、**at-rule 名側**の記法は網羅していない。DR-0047 の帰結に足した「CSS の読み込み宣言は記法で取りこぼさない」という主張と実装が食い違う。
- **失敗シナリオ**: `docs.css` へ `@IMPORT` で書くと検査は緑のまま通る。ただしレビュアーが `vite build` まで走らせて確認したところ、lightningcss が大文字の `@IMPORT` を import として解決せず落とすため、**現在のツールチェーンでは `dist/` への実際の混入は起きない**。検査ではなく minifier の挙動にたまたま守られている状態で、dev サーバーが配信する CSS には文字列がそのまま残る。
- **提案**: `walkAtRules(/^import$/i, ...)` にする。
- **対応**: 反映した。あわせて「大文字小文字を問わず列挙される」ことと、コメントアウトされた宣言を拾わないことをテストで固定した。
