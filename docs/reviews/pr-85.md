## should

### `decisions/undocumented-decision` — 別称の検査をどこで走らせ、何を除くかが決まっておらず、決めた本人の DR と生成物の `GLOSSARY.md` が落ちる

- **場所**: docs/decisions/0061-repository-language-lexicon-semantics-pragmatics.md:49（決定4）, :15, :38, :90
- **指摘した観点**: 検査ルールの実効性 / 決定記録（DR）との整合
- **累計**: 21回目
- **何が起きているか**: 決定4 は「使ってはいけない別称が文書中に現れたら落とす」とだけ書く。走査する場所も、別称に言及しているだけの文（例示・引用・禁止の説明）の扱いも、例外の型も無い。散文を走査する先例の DR-0046 は、正本自身（自己言及）と `docs/reviews/`（書き換えない履歴）を走査しないこと、決めた当事者の DR を例外の型にすることを DR で決めている。
- **なぜ問題か**: #81 の実装の中だけで守備範囲が決まり、DR に残らない。除外せずに例外登録で通すと、ファイル単位の例外がそのファイルの本物の別称まで黙らせる。
- **失敗シナリオ**: 「デザイン契約」を別称に登録し `docs/` を走査する → 生成された `docs/GLOSSARY.md` と DR-0061 の :15・:38 で `pnpm check` が落ちる → ファイルごと除外する → 以後 DR-0061 に書いた別称は検出されない。
- **提案**: DR-0046 と同じ粒度で除外の方針を決定4 に書く（走査しない場所、言及の扱い、例外の型と理由の要否）。具体的な一覧は実装に置く。

### `writing/ambiguous-criterion` — 決定4 の「その範囲でだけ落とす」は、文脈を複数持つ語や、両方の文脈にまたがるファイルで読みが割れる

- **場所**: docs/decisions/0061-repository-language-lexicon-semantics-pragmatics.md:28-30, :36, :50, :82
- **指摘した観点**: 日本語ドキュメント / 設計契約との整合 / 検査ルールの実効性
- **累計**: 17回目
- **何が起きているか**: 決定2 は文脈欄に別称を禁じるパスの範囲を書いてよいとし、決定4 は「その範囲でだけ落とす」とする。1語が範囲のある文脈と無い文脈を持つ場合、範囲の和でだけ落とすのか全体で落とすのかが読めない。文脈欄が「文脈ごとの意味」（語用）と「別称を禁じる範囲」（語彙）の2役を兼ねるので、意味は1つで一部のパスだけで禁じたい語は、決定2 の「割れる語にだけ」と同時に守れない。`docs/decisions/` と `README.md` のように両方の文脈にまたがるファイルを、範囲の内外どちらに数えるかも無い。
- **なぜ問題か**: #81 はこの DR を根拠にスキーマと検査を作るので、読み方の差がそのまま実装の差になる。
- **失敗シナリオ**: 「検査」の文脈欄に `design/` と範囲なしの2つを書く → 範囲の和で実装されると、`design/` の外では別称が落ちない。
- **提案**: 範囲指定をやめるか、語彙の層の欄へ移して規則を足す。
