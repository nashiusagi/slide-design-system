### `inspection/rule-never-executed` — セルフチェックの成果物を読む工程がどこにも無い

- **場所**: `docs/decisions/0057-self-check-before-ready.md`（「検討した他の選択肢」第1段）, `.claude/skills/pr-review/SKILL.md` 手順2 と手順4 のプロンプト雛形

- **累計**: 1回目
- **何が起きているか**: DR-0057 は「別のサブエージェントに読み返させる」案を却下する理由として「成果物を検証可能にすれば、**検証はレビュアーと人が既に通る工程の中でできる**」と書いた。しかし `pr-review` の手順2 の収集コマンドにも手順4 の雛形にも **PR コメントが含まれていない**。`grep` で確認したとおり、`pr-review/SKILL.md` に `comments` の記述は1件も無い。この差分は `pr-review/SKILL.md` に段落を1つ足したが、収集対象も雛形も変えていない。
- **なぜ問題か**: この段の肝は「主張ではなく検証可能な材料を残す」（決定3）で、却下案の比較もそこに乗っている。**材料が誰の入力にもならないなら、残るのは形式だけ整った自己申告**で、却下した「主張だけでよしとする」案と実質同じになる。申告を判定の入力にしない方針（DR-0052 / DR-0053）へ揃えたという主張の根拠が消える。

- **提案**: `pr-review` の手順2 の収集コマンドと手順4 の雛形へ `gh pr view <N> --comments` を足し、各観点が自分の守備範囲の項目を突き合わせる旨を1行書く。採らないなら、決定3 の却下理由を実態（材料は残すが突き合わせは任意）へ書き直す。

### `inspection/rule-has-bypass`（この PR で計上済み） — 「通した」の判定が内容の正しさを問わず、review-fix の差分を対象にしていない

- **場所**: `.claude/skills/issue-workflow/references/self-check.md`「この段を通した PR の数え方」, `.claude/skills/issue-workflow/SKILL.md` 手順6
- **指摘した観点**: 検査ルールの実効性
- **何が起きているか**: 判定基準は3つとも手続き的だ——`created_at` が Ready 化より前／無編集／各節に実体がある。**内容が正しいかは入らない。**

  **この PR 自身が反例になっている。** セルフチェックは3条件をすべて満たしたが、内容に誤りがあり、それを見つけたのはレビューだった（1周目・2周目でそれぞれ4観点が独立に指摘）。それでも `review_log.md` には `済` と記録されている。

  さらに構造的な問題がある。Ready 化（`2026-09-24T13:00:32Z`）より後に積まれたコミットが2つあり（`11ac4b6` / `5838105`）、**この PR で最も複雑な変更**（編集禁止ルールの追加、テンプレートの変更）がそこに含まれる。**Ready 化前の1回きりの自己点検は、review-fix ループで生まれる差分を最初から対象にしていない**（書式も要求していない）。「済」の意味は、その部分については「見た」ではなく「見ていない」に近い。
- **なぜ問題か**: 決定6 の効果測定は「通した PR」と「通していない PR」を比べる設計だが、**「通した」の中に、中身が誤っていて結局レビューに指摘された実例が最初から混ざる。** 指摘が減らない実例が積み上がっても、「段が効いていない」のか「『通した』の基準が緩い」のかを測定側は区別できない。
- **失敗シナリオ**: 実装者が Ready 化前の初期差分だけ丁寧に書いて「済」を確定させ、その後の review-fix で相当量の判断と説明文変更を行っても、それらは誰の自己点検も経ないまま「済」の1行に含まれる。
- **提案**: (a) 決定6 の測定対象を「Ready 化時点の初期差分」に限ると明記し、「済」の意味を縮める。(b) review-fix が一定量を超えたら追加のセルフチェックを求める。(c) 「セルフチェックの内容がレビューで訂正された回数」を別列で数える。
