## blocker

### `inspection/rule-has-bypass` — `implementsContracts` が `src/components/` 配下の全ファイル・全契約名の再定義検査を一括で外す

- **場所**: `packages/eslint-plugin-slide/src/rules/component-approved.mjs`:93-101（`checkShadow` 冒頭の早期 return）、`eslint.config.js`:99-107（`files: ['src/components/**/*.{ts,tsx}']`）
- **指摘した観点**: 検査ルールの実効性
- **累計**: 18回目
- **何が起きているか**: オプションは真偽値1つで、真なら `checkShadow` が何も見ずに return する。名前単位でも「そのファイルが実装している契約」単位でもないため、`src/components/` 配下のどのファイルでも4契約名すべてをローカル再定義できる。統合時に `npx eslint --stdin --stdin-filename src/components/Statement.tsx` で再現を確認した（報告0件。同じコードを `src/foo.tsx` として流すと `shadowed` で落ちる）。
- **なぜ問題か**: このルールの半分は「契約名を、契約と無関係なローカル実装で埋めていないか」である。除外の意図は「正規の実装が自分の契約名を定義できるようにする」ことだが、実装は「正規の実装の置き場所なら何でも素通り」になっている。DR-0050 の帰結が「`implementsContracts` を付ける場所は `eslint.config.js` だけに保つ」と書いて絞ったつもりの範囲より、実際の穴が広い。
- **失敗シナリオ**: `src/components/Statement.tsx` に `const Emphasis = () => <strong className="emph" />` を置き、`Statement` の中で使う。`Emphasis` は契約名だが正規の実装ではない（`index.ts` が公開するものとは別物で、クラスも `.emph`）。`pnpm lint` は通る。`.emph` は `components.css` に書かなければ `checkComponentClasses` にも当たらないので `pnpm design:check` も通る。App から `Statement` を使った時点で、契約の `emphasis` とは別物の強調が画面に出る。
- **提案**: そのファイルが定義してよい契約名だけを許す形にする。ファイル名（`Statement.tsx` → `Statement`）と一致する契約名の再定義だけを外し、それ以外は従来どおり弾く。

### `phase/runtime-capability-foreclosed` — `bullet-list` の `items: string[]` が、段階表示を箇条書きで使えなくしている

- **場所**: `src/components/BulletList.tsx`、`src/App.tsx`（bullets のスライド）

- **累計**: 1回目（新規）
- **何が起きているか**: `BulletList` が `ul` と `li` の生成を内側に抱えるため、`<Fragment>` で `li` を1つずつ囲めない。App.tsx の bullets スライドは、段階数 3 から 1 へ減った。DR-0050 は `string[]` を選んだ理由に契約の使い方を挙げているが、Fragment との関係には触れていない。
