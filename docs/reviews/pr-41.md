## blocker

### `decisions/dr-restates-canonical-value` — DR-0043 が正本の値（`space.lg` = 24、`type.lineHeight.normal` = 1.5）を本文に書き写した

- **場所**: `docs/decisions/0043-catalog-reads-generated-theme-css.md`（「文脈」節）
- **指摘した観点**: 決定記録（DR）との整合
- **累計**: 5回目
- **何が起きているか**: 「文脈」節が、単位を持たない葉の例として `design/tokens.json` の現在値をそのまま数値で書いている。
- **なぜ問題か**: `docs/decisions/README.md` は、値を含む決定には `**正本**:` 行を置き、値そのものは書かないと定めている。DR-0043 には `**正本**:` 行が無いまま数値が本文にある。正本を変えても DR の数値は追随せず、`pnpm theme:check` もこの記述は見ない。
- **失敗シナリオ**: `space.lg` を 24 から変えると、DR-0043 の本文だけが古い値を主張し続ける。読んだ人（AI を含む）が古い値を現在の契約だと誤認する。
- **提案**: 値を挙げずに「単位を持たない葉がある」と書く。トークン名の例示は正本のキーを指しているだけなので残してよい。

## should

### `contract/schema-order-assumed-as-semantics` — キャンバスの幅・高さを `design/tokens.json` のキー宣言順で決めており、その順序はどの契約も約束していない

- **場所**: `src/docs/pages/Foundations.tsx`（`CanvasFigure`）、`design/schemas/tokens.schema.json`（`canvas`）
- **指摘した観点**: 設計契約との整合 / コード品質（2観点から挙がった）
- **累計**: 1回目（新規）
- **何が起きているか**: `CanvasFigure` は `tokenEntries(node)` が返す葉の先頭2つを幅・高さとして使う。トークン名を書き写さないための選択だが、スキーマは `required: ["width", "height"]` で存在だけを要求し、並び順は制約していない。`Foundations.test.tsx` にキャンバスの枠を見るテストも無い。
- **なぜ問題か**: 正本が約束していない性質（オブジェクトのキー順）に意味を負わせている。順序が入れ替わっても、スキーマ検証も `pnpm theme:check` も落ちない。
- **失敗シナリオ**: `canvas` を `{ height, width }` の順に書き換えると、枠は 720x1280 で描かれる。`pnpm check` は緑のまま、カタログだけが誤った縦横比を見せる。
- **提案**: スキーマが名前の存在を約束している以上、名前で引く実装に変える（名前で引くのは値の書き写しではない）。順序依存を残すなら、その順序を契約として明文化し、テストで固定する。

### `inspection/raw-css-include-gap` — `?raw` で読んだ CSS が空でも落ちる場所が無く、`test.css.include` の列挙漏れが無検査の緑になる

- **場所**: `vite.config.ts`（`test.css.include`）、`src/docs/tokens.ts`
- **指摘した観点**: 検査ルールの実効性
- **累計**: 1回目（新規）
- **何が起きているか**: vitest は CSS の読み込みを空文字へ差し替える。`test.css.include` はその差し替えを解除する許可リストで、今は `design/theme.css` の1本だけ。列挙から漏れたファイルは、本番コードでもテストでも空文字として読まれる。
- **なぜ問題か**: DR-0043 の帰結はこの危険を文章で警告しているだけで、実行時に落ちる仕組みが無い。本番側とテスト側が同じ空文字から期待値と実測値を組み立てると、テストは緑のまま何も検証しない。
- **失敗シナリオ**: 後続のカタログページが `design/layout.css` を `?raw` で読み、`test.css.include` への追加を忘れる。その CSS を解釈するテストは、空文字どうしの比較で通る。
- **提案**: 読み込んだ CSS が空なら例外を投げる。列挙漏れは実行した瞬間に落ちるようになる。

### `writing/inaccurate-rationale` — `docs.css` の注釈が「長さも `--dh-*` からのみ取る」と言い切っているが、同じ差分が `1px` を書いている

- **場所**: `src/docs/docs.css`（冒頭の注釈と、`.doc-swatch` / `.doc-radius-box` / `.doc-canvas__frame` の `border`）
- **指摘した観点**: 日本語ドキュメント
- **累計**: 8回目
- **何が起きているか**: 冒頭の注釈は例外に触れずに「のみ」と書く。実装はヘアラインの `1px` を3か所で使っている。`design/rules.json` の `noRawScale.allowedLiterals` は `1px` を例外として認めている。
- **なぜ問題か**: このファイルは機械検査の対象外（DR-0042）で、注釈が唯一の規約になっている。字面と実装が食い違うと、後から触る側がどちらへも間違えられる。
- **失敗シナリオ**: 後続の実装者が注釈を信じて `1px` を消すか、逆に他の生の長さも許されると一般化する。
- **提案**: 注釈に `noRawScale.allowedLiterals` の例外を明記する。

### `writing/dangling-quote-reference` — DR-0043 が、DR-0018 に存在しない文言を鍵括弧付きで引用している
