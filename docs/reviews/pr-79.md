## should

### `contract/recorded-value-not-what-was-passed` — `対象コミット` をローカルの HEAD から取り、1周目が読むリモートの PR head と一致する保証がない

- **場所**: .claude/skills/pr-review/references/review-file-format.md:11, :67 ／ .claude/skills/pr-review/SKILL.md:52 ／ docs/review_log.md 前書き
- **指摘した観点**: 設計契約との整合 / 検査ルールの実効性 / 決定記録（DR）との整合
- **累計**: 2回目
- **何が起きているか**: 書式は `対象コミット` を「この周に見た head の SHA（`git rev-parse HEAD`）」とする。一方 `pr-review` の初回は `gh pr diff <N>`（リモートの PR head）を読み、手順1 は番号さえあればどのブランチからでも呼べる。記録する値と、レビューした対象の出どころが違う。
- **なぜ問題か**: DR-0060 決定5 がこの欄を足したのは、1周目が見た地点を後から確かめるためだ。別の SHA が入れば、その確かめが誤った入力で通る。
- **失敗シナリオ**: main をチェックアウトしたまま `pr-review 79` を呼ぶ、または push していないコミットがある状態で呼ぶ → PR head と違う SHA が入る → 基準値を下回ったときの確認が見当違いの地点を比べる。
- **提案**: 取得元を `gh pr view <N> --json headRefOid` に揃える。

### `writing/ambiguous-criterion` — 冒頭欄の `対象コミット` が、どの周の値で、再レビューで書き換えるのかを読み分けられない

- **場所**: .claude/skills/pr-review/references/review-file-format.md:11, :67
- **指摘した観点**: 日本語ドキュメント
- **累計**: 16回目
- **何が起きているか**: 冒頭欄は記録に1つしかない。その説明は「この周に見た head」で、注意書きは「初回は必ず書く」とある。再レビュー節の形には欄が無い。
- **なぜ問題か**: 「再レビューのたびに冒頭欄を最新の head へ書き換える」とも、「1周目の値を固定する」とも読める。前者で読むと、1周目の地点が消える。
- **失敗シナリオ**: 2周目の統合役が冒頭欄を2周目の head へ書き換える → Ready 化との比較で、1周目は Ready 時点を見ていたのに「足された」と判定される。
- **提案**: 「1周目に見た PR head。再レビューでは書き換えない」と固定する。

### `inspection/rule-has-bypass` — `立った観点` 欄の「結果なし」の注記を少し違う形で書くと、観点が欠けた PR が「全」と判定されて測定の母数に入る

- **場所**: scripts/count-first-round-findings.mjs:101-113（`readCoverage`）, scripts/count-first-round-findings.test.mjs:76-101
- **指摘した観点**: 検査ルールの実効性
- **累計**: 22回目
- **何が起きているか**: 「結果なし」は、要素の末尾が `（結果なし）` と完全に一致するときだけ拾われる。一方、照合に使う `normalizePerspectiveName` は括弧の中身を全部消すので、形の違う注記はそこで消え、その観点は「立った」と数えられる。`検査ルールの実効性(結果なし)` / `…（結果なし：タイムアウト）` / `…（途中で失敗）` は、どれも `status: 'full'` になる（統合で再現を確認した）。
- **なぜ問題か**: DR-0059 決定3・DR-0060 決定4 は「確かめられないなら母数に入れない」と安全側に倒す。書式を外れた記録ほど黙って母数に入るのは、その逆向きだ。
- **失敗シナリオ**: 1周目に検査観点がタイムアウトし、記録者が `検査ルールの実効性（結果なし：タイムアウト）` と書く → 「観点: 全」で母数に入る → 検査観点の指摘が無い分だけ計上回数が下がり、段の効果が大きく見える。
- **提案**: 各要素が「観点表の名前そのもの」か「名前 + `（結果なし）`」のどちらかに完全一致しなければ、読めないものとして欠けた側に倒す。変種をテストに足す。

## consider

### `inspection/commit-time-proxy-for-push-order` — Ready 化後のコミットの有無を、push の時刻ではなくコミット時刻で判定している

- **場所**: docs/review_log.md 前書き（`git log -1 --format=%cI <対象コミット>`）, docs/decisions/0060-self-check-measurement-aligned.md 決定5
- **指摘した観点**: 検査ルールの実効性
- **累計**: 1回目
- **何が起きているか**: 比べているのはコミットを作った時刻で、PR head に入った時刻ではない。
- **なぜ問題か**: Ready 化時点の差分は、その時点でリモートにあったコミットで決まる。コミット時刻ではそれを判定できない。
- **失敗シナリオ**: 10:00 にローカルでコミット → 10:05 に `gh pr ready` → 10:06 に push → 1周目 → コミット時刻が Ready 化より前なので「足されていない」と判定される。
- **提案**: 時刻ではなく SHA の一致で比べる。Ready 化の時点の head SHA を残し、1周目の `対象コミット` と比べる。
