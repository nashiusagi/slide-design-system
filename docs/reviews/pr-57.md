### `inspection/rule-id-mapping-incomplete` — 実装状況の判定根拠が measure 系にしか無いのに、DR と `$comment` が「どの method でも」と書いている

- **場所**: `docs/decisions/0051-catalog-rules-page-sources.md`:25, :73、`scripts/unimplemented-rules.json`:2、`scripts/validate-design.mjs`:257（`checkLintRuleCoverage`）, :291（`checkMeasureRuleCoverage`）, :416（`checkBypassFixtureCoverage`）
- **指摘した観点**: 検査ルールの実効性 / 決定記録との整合 / 日本語ドキュメント（3観点から独立に指摘）
- **累計**: 3回目
- **何が起きているか**: 「検査が通っている限り、ここに無いルールには実装が在る」の根拠として3つの検査が挙がっているが、免除リストと実際に突き合わせているのは `checkMeasureRuleCoverage` の `staleKnownUnimplemented` だけで、その相手も `IMPLEMENTED_MEASURE_RULE_IDS` に限られる。`checkLintRuleCoverage` はリストを引数に取らず、`checkBypassFixtureCoverage` は `method: "review"` を対象から外す。スキーマの `method` は review を許す。
- **なぜ問題か**: カタログは全ルールに「実装済み / 未実装」を断言するが、その断言を機械が守っているのは measure ルールだけになる。DR が却下案の欠点として挙げた「method ごとに根拠を足すことになる」が、採用案にもそのまま当たる。
- **失敗シナリオ**: `design/rules.json` へ `method: "review"` のルールを足す → 対応検査はどれも対象にせず `pnpm design:check` は緑 → `#/rules` は「実装済み」と表示し、人が判断すると決めたルールを自動検査が在るものとして見せる。
- **提案**: 断言の射程を lint / measure に限定し、review は判定の根拠を持たないことを DR の帰結と表示側の両方で扱う。
