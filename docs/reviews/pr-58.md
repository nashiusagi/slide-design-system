## 要約

blocker 1件、should 11件、consider 5件。blocker は DR-0052 の決定4（上限に達する前でもレビューを実行できなければ確認未了で抜ける）が、同じ DR の決定1・決定2（どちらも上限到達を条件にしている）と矛盾し、正本と宣言した `SKILL.md` にも反映されていない点。**5観点が独立に同じ場所を指した。** 字義どおり読むと、1周目のレビューが落ちただけでループを抜けられ、上限を設けた意味（DR-0025）が消える。

should は3系統に分かれる。(1) 抜け方の判定が上限到達を前提にしているかどうかが文書間で揺れる、(2) 判定の入力（未対応がゼロか）を第三者が再現できる形で残していない、(3) `pr-review` の出力ファイルへの書き込みを、その書式を持たない側の Skill が指示している。

## blocker

### `decisions/inconsistent-partition` — 決定4 が決定1・2 と矛盾し、正本の `SKILL.md` はどちらも実装していない

- **場所**: `docs/decisions/0052-review-loop-third-exit.md`（決定1・決定2・決定4）、`.claude/skills/issue-workflow/SKILL.md`（手順5）、`.claude/skills/issue-workflow/references/unconfirmed-comment.md`（冒頭の適用条件）
- **指摘した観点**: 決定記録との整合 / 設計契約との整合 / 検査ルールの実効性 / 日本語ドキュメント / コード品質（5観点から独立に指摘）
- **累計**: 2回目
- **何が起きているか**: 決定1 は確認未了を「上限を終え、未対応がゼロ」と定義し、決定2 も「上限に達したとき」と書く。決定4 だけが「上限に達する前でも、レビュー自体を実行できなかった場合…確認未了として抜ける」と書く。正本の `SKILL.md` 手順5 は「3周を終えた時点で数える」という枠の中に3つを並べており、上限前の離脱は書かれていない。`unconfirmed-comment.md` も「上限周回を終え」を適用条件にしている。
- **なぜ問題か**: この DR の中心は「いつ抜けてよいか」で、そこが DR 内部でも DR と正本の間でも割れている。字義どおりなら、1周目のレビュアーが落ちて未対応ゼロ（まだ指摘が1件も出ていない）なら、実質0周で抜けられる。既存の運用（`docs/reviews/pr-55.md`「レビューとして成立していないので収束の判定には使わない」＝その周を数えずにやり直す）を、明示せずに覆してもいる。
- **失敗シナリオ**: 2周目のレビュアーが落ちる → 未対応ゼロ → DR に従えば確認未了で抜け、`SKILL.md` に従えば3周目を回す。同じ状態から終わり方が割れる。
- **提案**: 「レビューを実行できなかった周は指摘ゼロとして数えず、やり直す。やり直しても走らせられないまま上限に達したときに確認未了」へ揃え、DR と `SKILL.md` と書式の3つで同じ条件を書く。

### `inspection/exit-condition-mismatches-state` — `consider` だけが残った周では確認未了に落ちるが、未確認の範囲が空になる

- **場所**: `.claude/skills/issue-workflow/SKILL.md`（手順5）、`.claude/skills/issue-workflow/references/unconfirmed-comment.md`
- **指摘した観点**: 検査ルールの実効性
- **累計**: 1回目（新規）
- **何が起きているか**: 収束は「指摘ゼロのレビューを1周通った」で、`consider` を含めれば指摘ゼロではない。一方で数えるのは `blocker` / `should` だけなので、`consider` のみを出して見送った周は収束でも打ち切りでもなく確認未了になる。だがその状態では最新のコミットまでレビュー済みで、未確認のコミット範囲が存在しない。
- **なぜ問題か**: DR-0052 が打ち切りについて挙げた却下理由（書式が想定していない状態を本文で打ち消す）が、新設した確認未了の側で再発する。回避しようとすると「`consider` だけなら指摘ゼロと見なす」と解釈を曲げる誘因になり、収束へ都合よく抜けられる。
- **失敗シナリオ**: 3周目が `consider` 2件のみ → 理由を残して見送る → 未対応ゼロ → 確認未了と判定 → 未確認の範囲が空で書式が埋まらない。
- **提案**: 「指摘ゼロ」の外延を手順5 に書く。`consider` を理由つきで見送った周は収束を妨げない、`consider` を直したならその修正は未レビューなので確認未了、と決める。

- **提案**: 未確認コメント・残指摘コメントに、その周までの `blocker` / `should` の対応結果一覧を必須項目として持たせる。
