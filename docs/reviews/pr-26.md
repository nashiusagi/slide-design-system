### inspection/rule-has-bypass — deck 参照が `../` を含むとき design/decks/ の外の任意ファイルを読み込める

- **場所**: `scripts/resolve-design-contract.mjs`（旧実装、`resolveManifestFile` 内の deck 読み込み）
- **指摘した観点**: 検査ルールの実効性
- **累計**: 9回目
- **何が起きているか**: 旧実装は `readFileSync(resolve(\`design/decks/${name}.md\`))` で manifest の deck 名をそのままパスへ埋め込んでいた。`name` に `../` を含めると design/decks/ の外にある任意の `.md` を deck として読み込めた（レビュアーが実行して再現を確認）。
- **なぜ問題か**: 「存在しない参照はエラーで止める」という DR-0013 の核となる保証が、deck に関しては「読み込みの成否」でしか担保されておらず、書き方を変えるだけで素通りした。
- **失敗シナリオ**: `{"decks":["../../../../secrets"]}` のような manifest で、design/decks/ の外にある deck 形式のファイルを解決結果に含められる。
- **提案**: deck 名を実ファイルの一覧（`readdirSync('design/decks')`）に対してのみ照合し、名前からパスを組み立てない。
- **対応**: 直した。`resolveManifestFile` が `design/decks/` の実在ファイルからのみ `deckSources` を組み立てるようにし、manifest の deck 名は辞書のキー照合にしか使わない構造にした。パストラバーサルの再現手順で再テストし、`Unknown deck reference` になることを確認した。
