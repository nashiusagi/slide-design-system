## should

### contract/value-outside-source-of-truth — Node バージョンをワークフローにリテラルで複製していた

- **場所**: `.github/workflows/check.yml`（`actions/setup-node@v4` の `node-version: 22`）
- **指摘した観点**: 設計契約との整合
- **累計**: 4回目
- **何が起きているか**: DR-0027 は Node バージョンの正本を `package.json`（`engines.node: ">=22"`）としているが、本PRは同じ値を `node-version: 22` としてワークフローへ直書きしていた。
- **なぜ問題か**: 将来 `engines.node` を変更しても CI 側は自動的に追従せず、更新を忘れるとローカルとCIのNodeバージョンが黙って乖離する。
- **対応**: `node-version-file: package.json` に変更し、`engines.node` を直接読ませる形にした。実際にCIで `>=22` から Node 24.20.0 が解決されることを確認した。

### phase/completion-criterion-not-verified-e2e — 完了条件2（ローカルとCIの結果一致の確認）がPR本文に記録されていない

- **場所**: PR #30 本文
- **指摘した観点**: フェーズスコープ
- **累計**: 4回目
- **何が起きているか**: Issue #29 の完了条件「実際に1本 PR を出して、ローカルの `pnpm check` と同じ結果になることを確認する」は、CI自体はgreenだったが、その確認を行ったことがPR本文（「作業中。」のまま）にもコメントにも記録されていなかった。
- **対応**: PR本文を仕上げる際に、実際にローカルで `pnpm check` を実行し結果が一致したこと、CIの実行ログ（run ID）を明記する。
