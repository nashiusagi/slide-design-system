#### `code/enumeration-line-pattern-too-broad` — 表の行の判定が広すぎ、パイプを含む地の文がブロックを繋いで誤検出になる

- **場所**: `scripts/check-canonical-duplication.mjs`（`isEnumerationLine` / `ENUMERATION_LINE`）

- **何が起きているか**: 先頭のパイプを省いた表を拾うために足したパイプ判定に行頭のアンカーが無く、`` `foo | bar` `` のようなコード例を含む地の文や、「前段 | 後段 の順で進む」という区切り記号としてのパイプまで表の行として扱われた。その行を挟んで離れた単発の言及どうしが1つのブロックに繋がり、複製でないものが報告される（両観点が別々の入力で再現を確認）。

- **なぜ問題か**: この一般則を読んだ人は、`design/decks/` への書き写しを穴だと気づけない。
- **反映**: 除外理由を分けて書いた——この検査が読む正本そのもの（対象にすると自己言及になる）と、layout 名を契約データとして持つ deck 契約。

#### `writing/term-inconsistency` — 同じ対象が「文書」「散文」「他の文書」の3通りで呼ばれている

- **場所**: `scripts/check-canonical-duplication.mjs` 全体、`docs/decisions/0046-...md`
- **指摘した観点**: 日本語ドキュメント
- **累計**: この PR では計上済み（1周目に計上）
- **何が起きているか**: 1周目の用語の揺れを部分的にしか直しておらず、検査の出力文言だけが「他の文書」に変わって、同じファイルの JSDoc は「散文」のままだった。
- **なぜ問題か**: 検査が見ているのが「散文」なのか「文書全般」なのかが、ファイル内の記述だけからは決まらない。
- **反映**: スクリプト内を「文書」へ統一し、DR では文脈で「散文（生成できない文章）」を一度定義してから以後を「文書」に揃えた。

#### `writing/ambiguous-criterion` — 例外の切り分け基準が、実在する例外の型を分類できない

- **場所**: `docs/decisions/0046-...md` 帰結、`scripts/canonical-duplication-allowlist.json`
- **指摘した観点**: 日本語ドキュメント
- **累計**: この PR では計上済み（1周目に計上）
- **何が起きているか**: 「当事者なら例外、後から参照しているだけなら書き換え」という二分法を足したが、登録済みの例外には「無関係な値が偶然一致しただけ」「その場所から正本を参照する手段が無い」という第三・第四の型が含まれており、二分法ではどちらとも言えない。
- **なぜ問題か**: 手順として指定した基準が、実在の過半を分類できない。次に迷ったとき判断が割れる。
- **反映**: 例外にしてよい理由を型として列挙し、当てはまらないものは書き換える、という形へ直した。

### consider

- `inspection/allowlist-entry-overbroad`（この PR では計上済み）— `count` は総件数しか見ないため、同じファイル・同じ正本で「登録済みの複製が消え、別の箇所に同数の複製が生まれた」入れ替わりを検出できない。行番号を持たせると無関係な編集のたびに例外が壊れるため、直さずに DR の帰結へ既知の限界として書いた。
- `inspection/false-positive-forces-allowlist`（この PR では計上済み）— 空行でブロックを切らなくしたため、別々の話題の項目が同じ箇条書きに並び、それぞれ別の名前に触れていると複製として報告する。Markdown としては1つの箇条書きであり、話題の違いは機械には見えない。誤検出を避けるために離して書けるようにすると、離すだけで抜けられる。トレードオフとして現状を選び、DR の帰結へ既知の限界として書いた（1周目の should から重要度を下げたのは、検出漏れと誤検出のどちらを取るかの判断であり、実装の誤りではないため）。
- `contract/source-of-truth-ambiguous`（6回目）— レイアウト追加の判断基準が `DESIGN.md` と `.claude/skills/pr-review/agents/phase.md` にほぼ同一の文言で複製された。反映: 基準は `DESIGN.md` が持ち、Skill 側は参照だけを持つ形へ直した。
- `phase/out-of-scope-addition`（この PR では計上済み）— 走査対象を `experiments/` まで広げたことは Issue #42 の「やること」の列挙に無い。前周の `inspection/rule-coverage-partial` への直接の応答であり、除外方針は DR に明文化されている。このまま入れる判断とし、PR 本文に理由を書いた。

### 落とした指摘

- `inspection/allowlist-entry-overbroad`（同値の正本が複数あるとき、1つを名指しした例外が他方の複製も抑える）— 文書に書かれている値が同じである以上、どちらの正本を写したのかは原理的に区別できない。報告も1件で、在り処をすべて挙げている。1周目の `contract/allowlist-key-tracks-canonical-values`（在り処の連結を完全一致で照合すると、無関係なトークンの変更で例外が壊れる）と反対方向の要求でもある。限界として DR に書き、照合は現状のままとした。
